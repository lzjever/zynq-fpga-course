## 3. 定量核查:三个技术硬伤(请 reviewer-tech 复核,我方核算过程附上)

这是本意见书最重要的部分——对方方案的**现象骨架**里有两处算错/写错,若直接成书,学员会在板上/仿真器里看到与书相反的结果,杀伤力远大于措辞问题。

### 3.1 "降 9600 波特"兜底方向完全反了(§7 / §11.1)

对方设计:115200 一帧 = 4340 点,深度 8192 够(✓ 这步对);若免费档深度受限,"备选 9600 波特——一帧 289µs@50MHz 采样=14462 点"。

核算:**9600 波特一个位 = 104.17µs,一帧 10 位 = 1041.7µs;@50MHz 采样 = 52,083 点,是 8192 深度的 6.4 倍——只能抓到 1.57 个位。** "289µs"对应的是 34.6kbaud,不是 9600,除算错误。方向也错了:ILA 采样时钟固定 50MHz,**波特率越低、一帧点数越多**。正确兜底是升波特率(230400 → 2170 点;921600 → 542 点)或窗口触发对准起始沿。主线 115200(4340<8192)本来就安全,兜底删掉或改写即可,但**按现稿写进书,学员照做必翻车**。

### 3.2 理想 RTL 仿真里二进制计数器根本不会"撕裂"(§4 第 1 层)

对方主现象:"TB 用两个真异步时钟(20.000ns/20.003ns)驱动 binary 计数器跨域采样,几微秒内必然抓到撕裂值(7→15)"。

核算:Verilog 非阻塞语义下,源时钟沿调度的各位更新在**同一时间片内原子完成**;目的时钟沿无论落在何处,采样到的要么**全旧**要么**全新**——拍频扫描扫的是采样相位,扫不出"半新半旧"。**零延迟理想 RTL 仿真里,这个实验永远显示"干净",恰好证明不了对方要证明的观点。** 真实世界的撕裂来自各位布线延迟不等,而 XSIM 的理想模型里没有它。

修复方法简单且教学上更好:**给各位显式注入不同延迟**(如 `assign #1.2 b0=...; assign #1.7 b1=...;` 模拟布线偏斜)。加了偏斜,对方"几微秒必然撕裂"的时长估算反而成立(偏斜窗口 200ps / 20ns ≈ 1%,平均每百次翻转撕一次 ≈ 每 2µs);更妙的是,**同一偏斜模型下 Gray 版永远干净**——对方的"全课最有力的一张图"(binary 撕裂 vs Gray 干净并排)必须靠偏斜注入才能成立,且"撕裂 = 到达时间不齐"这一物理原因被显式可见。请 tech 复核后把偏斜注入写进 cdc_demo 的规格。

### 3.3 `force 1'bx` 教不了亚稳态收敛(§4 第 2 层)

对方:"TB 里 force 同步器第一拍输出为 1'bx 一拍……打两拍后第二拍大概率收敛到 0 或 1。"

核算:四态仿真里 **X 进 X 出**——第二拍采样 X,输出还是 X,不会"大概率收敛"。学员会看到"书说会好,波形没好",对一个以较真著称的学员这是信任级事故。

修复建议(比修 demo 更好,改立意):把第 2 层替换为"**仿真器的盲区**"小节——当场演示两件事:X-传播不收敛;零延迟不撕裂。结论:"XSIM 假装每个触发器都完美,它根本不给你演亚稳态——所以这一课只能讲道理(MTBF)+ 买保险(打两拍),不能做实验。"知道工具不能告诉你什么,和知道它能告诉你什么,是同一级工程素养。这一节同时安放对方已知坑③"force 只能用在 TB,防学员模仿"。

## 4. 各 Lab 现象的教学质询(逐条)

### 4.1 Lab02 裸版对比:现象成立,但归因要写两笔(变量控制问题)

裸版"按一次乱翻"确实是抖动的存在性证明,但**裸版乱翻有两个原因**:机械抖动(主要、人眼时间尺度)+ 异步信号直接当使能(次要、ch03 的雷)。裸版 = 无同步、无滤波、无边沿检测,与消抖版之间的差异变量不止一个。第二章**不得**断言"乱翻全是抖动造成";正确写法:"现在我们修掉主要原因;还有一个更阴险的次要原因,下一课翻案。"——这本身就是给 ch03 的第二颗雷,比我只埋"直接接进时钟域"一句更具体。采纳对方实验,归因措辞按此修正。

### 4.2 Lab03:三层结构骨架好,两处已由 §3.2/3.3 修正;第三处——clk_wiz 必须移出主线

对方把"第一个 IP(clocking wizard)"塞进全课程**最抽象**的一章,只为一个自标"需实测、不明显就砍"的选做彩蛋服务。这违反每章 ≤2 新概念的红线(亚稳态+CDC 已满载,再加 PLL/IP 生成三连)。且主线三层(撕裂仿真/盲区/板上正确链)完全不需要它——TB 双时钟是仿真里生成的,板上正确链只用 N18。**裁定:clk_wiz 及"IP 是什么"随彩蛋走选做附录;若彩蛋实测可看,IP 三步操作自成小节。**"第一个正式 IP"的名分改给 ILA 章(ch08,create_ip ila,对方自己的显式例化方案)。

### 4.3 Lab05 扩展为收发自环:方向完全正确,但作为单章是难度自杀,必须拆章

对方论点"发送器在板上没有观察者"成立,自环是漂亮的解法,我接受扩展。但请看对方自己的数字:uart_tx 85 行 + uart_rx 80 行 + uart_top 50 行 + tb 120 行,"全课最大 Lab ~340 行"——塞进**全课程认知负荷顶点章**(FSM 首次登场)。原设计里 ch07 的新概念预算是:FSM + 帧协议 + 移位寄存器,已经顶格;现在变成两个 FSM + 协议 + 集成 + 飞线排错。**把课程最重的一页放在流失率最高的一页,这是学习曲线上的自杀设计。**

拆章方案(合并蓝图采用):
- **ch06 · UART 发送器**(教学式):FSM 首登场,状态图→代码逐弧映射,TB `$write` 打印 "Hello PL!"。~3-4h,方差小。
