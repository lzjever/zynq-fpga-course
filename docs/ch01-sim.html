CHAPTER 01

仿真入门:在波形里看见时间

半亮是这世界对你撒的第一个谎,波形不会撒谎——今天领你的免费时间显微镜。

钩子:两桩悬案,一台显微镜

上一章(ch00)留下了两桩悬案:

  1. "半亮"之谜:把 LED 接到 cnt[0],LED"半亮"。可数字电路只有 0 和 1,哪来的"一半亮"?我们说是 25MHz 闪太快——谁看见了?你手边没有示波器。
  2. "testbench"之谜:Lab02 的需求书里赫然写着"testbench 骨架"五个字。它是什么?为什么你的第一份从零作业会需要它?

两桩案子,同一台破案工具:仿真器(Simulator)——一块不要钱、不要烙铁、不要示波器的"时间显微镜"。它在你电脑内存里按你的描述把电路"演"出来,把每根导线在每一纳秒的值画成图。这一章我们用它解剖你已经完全理解的 led_blink.v(解剖熟悉的电路,零风险),顺便把写测试台的手艺学会——Lab02 马上要用。

知识 · 看电路的三种方式

算(ch00 的公式:第 N 位方波频率 = 时钟 ÷ 2N+1)、仿真(今天:在软件里演电路)、上板(以后:真实硬件 + 在线逻辑分析仪)。工程师三者都用,先用最便宜的那个。仿真一次几分钱电费,烧板一次几分钟工夫——先仿真,后上板,是全课程的固定节拍。

目标:读完这章你能

  1. 说清测试台与被测电路的本质区别,并举出两个"只在测试台里合法"的语法;
  2. 把 lab01 的测试台跑起来,在波形窗口里加信号、放游标、量周期;
  3. 用游标量出 cnt[0] 的周期是 40ns(= 25MHz),亲手给"半亮"结案,并用三句话说清眼睛为什么被骗;
  4. 解释为什么"看见 cnt[23] 翻一个整周期"在仿真里不划算,以及公式如何替你跑完剩下的一千六百万拍;
  5. 用命令行三步舞(xvlog → xelab → xsim)跑仿真——给命令行高手的顺手兵器。

原理:测试台是什么

测试台(Testbench, TB)是写给仿真器的软件,不是电路。它像一台实验台:被测电路摆在台子中央,测试台负责拨开关(造激励)、喂信号(造时钟)、然后盯着每根线的电压随时间变化(看波形)。它永远不会被做成硬件。

图 1 · 测试台包住被测电路:造时钟、造激励、说停;被测电路的每根线都被"录像"

被测电路行话叫 DUT(Device Under Test,被测器件)。注意一个甜头:仿真器能看到 DUT 内部的每一根线——cnt 的每一位、每根导线的中间值,统统可看。软件里你打个断点才能看变量,仿真里默认全程录像。这个特权后面每一章都在用。

测试台三要素:造时钟、造激励、说停

任何测试台,剥到骨头就三件事:

要素干什么典型写法
① 造时钟给 DUT 一颗"假晶振"——周期与板上 N18 一致(20ns)always #10 clk = ~clk;
② 造激励扮演外部世界:按下/松开按键、送数据、复位……initial begin … end 里按时间顺序拨信号
③ 说停告诉仿真器"演到这儿收工"(否则它永远演下去)$finish;

两种方言:可综合的,和只给仿真器看的

ch00 说过,Verilog 是"电路的描述文案"。但那只是半张地图——Verilog 还有另一半:写给仿真器的软件方言。前者叫可综合子集(Synthesizable Subset):只有它能被综合(Synthesis,把描述翻译成真电路的步骤)接受;后者永远活不到上板那天,却是测试台的日常用语。两页语法,一种语言:

写法方言意思
always @(posedge clk) / assign可综合 ✅造电路(ch00 全篇讲的就是它)
#10仅仿真 ⚠️"过 10 个时间单位再往下走"——真实电路里不存在"等待"
initial begin … end仅仿真为主 ⚠️"开机时按顺序执行一遍"——顺序执行的"软件句子"
$display / $finish仅仿真 ⚠️系统任务(System Task):打印/收工,长得像函数调用,因为它们本来就是给"软件"用的
repeat (20) @(posedge clk)仅仿真 ⚠️"等 20 个时钟上升沿"——测试台的循环等待
知识 · "终于有一段 Verilog 像软件了——因为它本来就是软件"

测试台里可以用顺序、循环、打印、随机数,你写 C 的手感全回来了。这不是巧合:测试台的本职就是一段"扮演外部世界"的程序。规则只有一条:这些写法永远别混进被测电路(.v)里——综合器遇到 # 或 $finish 会直接报错(它没法给"等待"造一块硬件)。怎么避免混错位置,见本章"常见坑"第一条。

仿真时间 ≠ 物理时间

波形横轴是仿真时间(Simulation Time):一个纯粹的数字,单位由文件开头的时间标度(Time Scale)决定:

`timescale 1ns/1ps   // 时间单位 = 1ns,#10 就是 10ns;最小刻度(精度 Precision)= 1ps

一句话记法:斜杠前是"一块钱多大",斜杠后是"最小分币多小"。我们的板子时钟周期 20ns,所以 1ns 作单位正舒服。注意两件事:第一,仿真时间走得多快取决于电脑性能,与电路真实速度无关——仿真 0.336 秒的电路行为,电脑可能要真跑几十秒;第二,忘了写这行,或单位写错,所有 # 延时全部错位(下一章有个"20ms 变 20ns"的经典假通过,先在这里打预防针)。仿真器每推进一次最小刻度,算一遍所有电路的值——这个最小节拍叫时间步(Time Step)。

动手:五分钟跑通第一个测试台

第 0 步:拿到文件

课程已为 lab01 配好测试台 labs/lab01-blink/tb_led_blink.v 和一键脚本 sim.tcl。测试台核心代码不到 20 行,每行都有注释:

`timescale 1ns/1ps          // 时间单位 1ns,最小刻度 1ps(#10 = 10ns)

module tb_led_blink;        // 测试台没有端口——它包住被测电路,不对外伸引脚

    reg  clk   = 1'b0;      // 造时钟用的拨动开关(reg 在测试台里就是我们熟悉的"变量")
    reg  rst_n = 1'b0;      // 按键:先按住(0=按下),等电路清零完再松手
    wire led;               // 接被测电路的输出:一根"观察用导线"

    // ---------- 被测电路(DUT)----------
    led_blink dut (
        .clk   (clk),
        .rst_n (rst_n),
        .led   (led)
    );

    // ---------- 要素 ①:造时钟(10ns 翻一次 = 周期 20ns = 50MHz,与 N18 同款)----------
    always #10 clk = ~clk;

    // ---------- 要素 ②:造激励 + 要素 ③:说停 ----------
    initial begin
        repeat (20) @(posedge clk);   // 按住复位 20 拍,让计数器从 0 起步
        rst_n = 1'b1;                 // 松开按键,电路开始自由跑
        repeat (200) @(posedge clk);  // 再跑 200 拍:足够看清 cnt 低位的翻转规律
        $finish;                      // 收工:告诉仿真器"到此为止"
    end
endmodule

三要素各就各位。注意两个细节:测试台自己就是顶层(它包着 DUT,没人包它);DUT 的接法 led_blink dut (...) 是"模块例化"——把一块已知电路摆进更大的图里,ch05(PWM 呼吸灯)正式教,今天照着抄即可。

第 1 步(GUI 路):把测试台放进对的筐

步骤 · Vivado 2026.1(先开着你熟悉的 lab01 工程)
  1. 菜单 Add Sources → 选 Add or Create Simulation Sources(注意:不是 Design Sources!)→ Add File → 选 tb_led_blink.v → Finish。
  2. 看一眼 Sources 窗口:多出一个 Simulation Sources → sim_1 文件夹,tb_led_blink 躺在里面(它是仿真的顶层,自动识别)。
  3. Flow Navigator 左侧 SIMULATION → Run Simulation → Run Behavioral Simulation。等十几秒,Vivado 切到仿真工作区,弹出波形窗口。
  4. 波形窗口默认只演 1000ns(约 50 拍)——不够。点工具栏 Run All(快捷键 F3),让仿真一路跑到我们的 $finish(约 4.4µs)。

第 2 步:把信号请进波形,学会读它

波形窗口 = 时间的照片。三个零件:

  • 横轴 = 仿真时间(单位 ns,取决于 timescale);
  • 每行 = 一根信号线:斜坡是翻转,平线是保持;多位信号(如 cnt)默认显示十六进制值,点名字前的 + 号可展开成 cnt[0]、cnt[1]……每一位;
  • 游标(Cursor)= 一把卡尺:在波形上点一下,游标会自动吸附到最近的翻转沿,顶部显示绝对时刻。量周期:把游标吸在某个上升沿记下 t1,再吸到下一个上升沿记下 t2,周期 = t2 − t1。

操作:左侧 Scopes 面板选中 dut → 右侧 Objects 面板找到 cnt(或直接在波形里右键信号 → Add to Wave Window 都行)→ 把 cnt[0]、cnt[1] 拖进波形。然后你将看到本章的"物证":

现象与验证:两桩悬案,一次了结

图 2 · 波形阅读法(复位松开后的稳态,示意):每行一根信号,游标吸附在 cnt[0] 的两个相邻上升沿上,Δ = 40ns

悬案一收案:"半亮"的真相

在波形里量 cnt[0]:它每个时钟上升沿翻转一次,游标读数 Δ = 40ns,即 25MHz——和 ch00 的预测分毫不差。现在用三句话说清"半亮":

  1. LED 确实在一秒内亮灭两千五百万次,占空比一半一半;数字电路上没有"半亮",只有高速翻转。
  2. 人眼对每秒超过几十次的闪烁就会"融合",感受到的只是时间平均值:50% 的时间亮 → 感觉"半亮"。
  3. 所以"半亮"不是电路的行为,是你的眼睛在低通滤波——眼睛替你把 25MHz 平均掉了。波形显微镜不会平均,所以它看得见真相。
里程碑 M1 · 第一次看见时间

你在波形里亲手量出了 25MHz,悬案结案。记住这个手感:以后每次电路行为和直觉不符,第一反应就是"扔进仿真里看一眼"。顺便剧透:ch05(PWM 呼吸灯)我们会故意利用"眼睛会平均"这同一个原理,造出真正可调的半亮——敌人变工具。

悬案二收案:testbench 就是你刚跑的东西

Lab02 需求书里的"testbench 骨架"不再神秘:造时钟、造激励、说停。区别只在激励——Lab02 的测试台要扮演一颗会抖动的按键(按一次,信号在 20ms 里弹跳几十次),还要自动判分打 PASS/FAIL。下一章手把手。

练习:量三个位,验证一条定律

别停下,趁热做一份数学验证(ch00 的公式值得亲手复查一遍,别忘了这门课的座右铭):

  1. 游标量 cnt[0] 周期 → 应为 40ns;再量 cnt[1] → 应为 80ns;再量 cnt[2] → 应为 160ns。位号每加 1,周期翻倍。
  2. 由此外推:cnt[23] 周期 = 20ns × 224 ≈ 0.336 秒(LED 约 3Hz 闪烁,与你板子上看到的心跳一致)。
  3. 那为什么不直接在仿真里看 cnt[23] 翻一个整周期?算一笔账:那要仿 1600 多万个时钟周期。电脑每秒能仿大约百万拍上下,意味着几十秒到几分钟的等待,换来一个公式已经告诉你的答案。工程师的选择:低位量三次,定律成立,公式推高位。仿真很便宜,但不是免费的——这是第一次也不会是最后一次做这笔账。(下一章还有更聪明的省钱法:把电路参数改小,小电路验证大逻辑。)

命令行路:三步舞 + 一键脚本

GUI 三步(加文件、跑仿真、看波形)对应的其实是三条命令——Vivado 的仿真器叫 XSIM(Xilinx Simulator),它有自己的命令行三步舞:

# ① 编译:xvlog 把 .v 翻译成仿真器格式(被测电路 + 测试台一起)
xvlog led_blink.v tb_led_blink.v

# ② 装配:xelab 把测试台连成一个可运行的"仿真快照(Snapshot)"
#    -debug typical 让波形里能看到电路内部信号(不加就只有顶层端口!)
xelab -debug typical tb_led_blink -s tb_led_blink_sim

# ③ 运行:xsim 跑快照。-R = 一路跑到 $finish 自动退出(终端打印模式)
xsim tb_led_blink_sim -R
#    想开波形窗口:去掉 -R 换成 --gui

课程把它包成了 labs/lab01-blink/sim.tcl,一条命令:

vivado -mode batch -source sim.tcl    # 在 labs/lab01-blink/ 目录下

下一章 Lab02 的测试台会自动打印 PASS/FAIL——那才是三步舞的主场:改一行、跑一条、看终端,快得像跑单元测试。

常见坑

坑 1 · 测试台放错筐(今天最常见的坑)

把 tb_led_blink.v 当 Design Sources(设计源)加进去,综合就会试图把测试台造成电路——它撞上 #10、$finish 这些"软件方言"直接报错(类似"unsupported system task"),或者被两个"顶层模块"搞混问你谁是 top。自救:Sources 里右键该文件 → Remove File from Project,再按第 1 步重新加进 Simulation Sources。记住口诀:Design Sources 筐放电路,Simulation Sources 筐放测试台——两个筐,两种命运。

坑 2 · 波形停在 1000ns,以为电路死了

Run Behavioral Simulation 默认只演 1000ns(约 50 拍)。我们的测试台要跑 220 拍——不是电路错了,是没演完。点 Run All(F3)跑到 $finish,或在 Tcl 控制台敲 run -all。凡是"波形结尾突然全变平/全变X",先怀疑是"演完了"而不是"坏了"。

坑 3 · 忘了 $finish(或忘了它只是测试台的)

测试台没有 $finish:Run All 会一直演下去,电脑风扇起飞——仿真时间是无限的,电路自己不会喊停。反过来,把 $finish 写进被测电路 .v 里,则会在上板前的综合时报错(见坑 1 的原理)。

坑 4 · 命令行跑完波形里没信号

xelab 不加 -debug typical,快照里只留顶层端口,cnt 这些内部信号在波形里根本不存在。GUI(Run Behavioral Simulation)自动带调试信息,命令行要自己记得加——这也是 sim.tcl 替你写死它的原因。

如实交代 · XSIM 免费档的限制

免费档(BASIC 授权)的 XSIM 限制:一次仿真最多约 50000 个设计实例(触发器/门级单元的计数)。lab01 总共 24 个触发器加一点逻辑,离限额差三个数量级;后面最大的设计(ch08 的总线从机)也到不了零头。这个限制真正影响的是"仿真整颗 SoC"那种规模的活——到时候你会换工具,而不是换钱包。

小结

本章一句话

测试台是写给仿真器的软件:造时钟、造激励、说停;波形是时间的照片:横轴时间、每行信号、游标量距。半亮悬案结案——眼睛会平均,波形不会。你已经会用 GUI 和命令行两条路跑仿真,并且知道仿真便宜但不是免费。

三档自测

A · 概念(用人话说,禁止背定义)

1. 测试台和被测电路,一个像软件一个像硬件——用你自己的话说,区别的本质是什么?各举一个只有对方能用的语法。

2. 为什么 led_blink.v 里绝对不能写 #10?

看答案(先自己说一遍)

1. 被测电路是"电路的描述",会被综合成真硬件,活在上板之后;测试台是"扮演外部世界的程序",只活在仿真器里,永远不上板。只有测试台能用 #延时、$display;只有被测电路里的 assign/always @(posedge clk) 有"造硬件"的含义(测试台里写它们通常只是摆设或造时钟)。
2. #10 的意思是"等 10ns 再继续"——真实电路里没有"等待"这个元件,综合器无法为它造硬件,直接报错。等待是软件世界的概念,电路里只有"时钟继续走"。

B · 预测(先猜,再跑)

把测试台的时钟从 #10 改成 #5(周期 10ns = 100MHz),被测电路一行不动。重跑仿真,cnt[0] 的周期读数变成多少?板子上的 LED 会不会因此变快?

看答案(先写下你的预测)

波形里 cnt[0] 周期变为 20ns(翻转间隔 10ns)——仿真时间轴上的读数跟着假晶振走了。但板子毫无变化:真电路焊死在 N18 的 50MHz 上,而 N18 是焊在板子上的真晶振,不受测试台摆布。这就是"仿真时间 ≠ 物理时间"的另一面:测试台的时钟是假设。反过来,如果你真想改板子上的速度,要改的是被测电路(比如 ch00 实验里换 cnt 的位),而不是测试台。

C · 排错(找出 bug,说清现象)

同学把测试台写成这样,仿真也跑起来了,波形却从头到尾全平:cnt 恒为 0,led 恒为 0。哪里错了?

reg rst_n = 1'b0;
initial begin
    repeat (200) @(posedge clk);
    $finish;
end
看答案(先自己指认)

复位从未释放:rst_n 初始化为 0(按下)之后,激励里忘了写 rst_n = 1'b1;,按键被"按住"了整个仿真。电路一直在执行清零计划,没有任何报错——这是仿真最阴的一类坑:不报错,只是安静地什么也不做。排错思路:波形全平/全 0,先查复位和使能类的激励,再怀疑电路。
