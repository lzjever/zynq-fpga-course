CHAPTER 05

PWM 呼吸灯与模块例化

数字世界没有 0.5V——但你的眼睛会替你算平均。这次我们故意造"半亮",还要让它学会呼吸;顺便解决你憋了三个 Lab 的烦躁。

1 · 钩子:第三次抄 tick 之前,你烦躁了吗

数一数:lab01 的闪烁,靠一个 24 位计数器;lab02 的 20ms 消抖,又写一遍"数满 N 个时钟";ch03 的压测激励里,还是计数。写软件出身的你,DRY(Don't Repeat Yourself,不要重复自己)的本能早就痒了:同一段"数满 N 产一拍"的逻辑,凭什么抄第三遍?

电路世界当然能抽——而且比函数更彻底:抽成一个模块,它就成了一颗独立存在的芯片;哪里要用,就"摆一颗"进去,两颗、三颗并行工作,互不打扰。这个"摆一颗"的动作,就是模块例化(Module Instantiation),今天的主角之一。

主角之二借个旧悬案开场:ch00 实验 2 里,LED "半亮"把你骗了——那是 25MHz 翻转骗过了眼睛的意外。今天反过来利用这个生理漏洞,故意、精确、可调地造出 0 到 255 共 256 档亮度,再让它顺滑地涨落——呼吸灯。今晚结束时,你的板子会像睡着了一样。

2 · 这一章要学会什么

  • 能解释 PWM 为什么能用 0/1 造出中间亮度(占空比 → 时间平均 → 人眼滤波);
  • 能算出 8 位分辨率 @50MHz 的载波频率(50M ÷ 256 ≈ 195kHz),并说明人眼为何看不见闪烁;
  • 能把 led_blink 重构成"例化 tick_gen"的版本,并说出函数调用与例化的三点差异;
  • 会用 parameter 给模块传参数(#(.DIV(...)) 语法),理解 $clog2 自动位宽;
  • 能实现"三角波亮度 + 载波相位 + 比较器"的 PWM,板上看到约 4s 的呼吸,并按住按键验证 duty=0 全灭;
  • 能踩准比较器的边界陷阱(phase<duty 与 phase<=duty 的差别)。

3 · 原理:占空比 = 平均亮度

脉冲宽度调制(Pulse Width Modulation, PWM):输出只有 0 和 1,但高电平占整个周期的比例可以任意调。这个比例叫占空比(Duty Cycle)。LED 亮不亮取决于一段时间里的平均电流——只要周期够快,眼睛(和 LED 的惰性)就像一个低通滤波器,只看得见平均值:

图 1 · PWM:0/1 的方波,靠"高电平宽度"编码亮度,靠人眼/LED 的惰性还原成模拟量

两个设计旋钮:

  • 载波频率(Carrier Frequency):方波跑多快。我们的实现是"一个 8 位计数器每拍 +1",每 256 拍一圈 → 50MHz ÷ 256 ≈ 195.3kHz,周期 5.12µs。人眼暂留约几十赫兹,195kHz 安全四个数量级——你绝不会看见频闪。(反过来,载波降到 100Hz,LED 就开始"嗡嗡闪",自测题里让你推一遍。)
  • 分辨率(Resolution):亮度分几档。8 位 = 256 档,呼吸已经绸缎般顺滑;档位越多,占空比颗粒越细,但载波频率也要越高(或加长周期)。8 位是这个应用的标准答案。
知识 · 这招你家里到处都是

PWM 调光、调速、调音量:显示器背光、风扇、舵机、Class-D 音放……"数字系统造模拟效果"的第一工具。Zynq 的 PS 侧硬件 PWM 外设原理相同——而你今天用 55 个 LUT 手搓了一个。

4 · 动手一:先拿老朋友开刀——led_blink 例化版

新零件 tick_gen.v(完整带注释版在 labs/lab05-pwm/tick_gen.v):

// 数满 DIV 个时钟,发一个单周期脉冲。DIV 任意整数(≥2),不必是 2 的幂
module tick_gen #(
    parameter DIV = 390_625          // 参数:多少个时钟一个 tick
)(
    input  wire clk,
    input  wire rst_n,
    output reg  tick                // 高电平恰好 1 拍
);
    localparam W = $clog2(DIV);       // 需要几位计数器:clog2(390625)=19
    reg [W-1:0] div_cnt;

    always @(posedge clk) begin
        if (!rst_n)              begin div_cnt <= 0; tick <= 1'b0; end
        else if (div_cnt == DIV-1) begin div_cnt <= 0; tick <= 1'b1; end
        else                    begin div_cnt <= div_cnt + 1'd1; tick <= 1'b0; end
    end
endmodule

然后是仪式性的时刻——led_blink 不再自己数数,改成例化:

module led_blink2 (
    input  wire clk,
    input  wire rst_n,
    output reg  led                 // 注意:从 wire 变成了 reg(现在它在 always 里翻转)
);
    wire tick;                          // 一根内部导线,准备接零件的输出

    tick_gen #(.DIV(2**23)) u_tick (   // 摆一颗零件,DIV=2^23
        .clk   (clk),                   // 端口按"名字"接线,永不接错
        .rst_n (rst_n),
        .tick  (tick)
    );

    always @(posedge clk)
        if (!rst_n)    led <= 1'b0;
        else if (tick) led <= ~led;   // 每 2^23 拍翻一次 → 50M/2^24 ≈ 2.98Hz
endmodule

验算一下连续性:每 223 拍翻转一次,周期 = 2×223 = 224 拍 → 50M ÷ 224 ≈ 2.98Hz。和 lab01 的 cnt[23] 一拍不差——同一件事,两种写法,而这一种从今天起只写一次。

知识 · 函数调用 vs 模块例化(三点差异)

① 存在方式:函数调用是"用完即走";例化出的子电路永久存在、永远上电——例化两次就是两块真实电路并行工作,不是"调用了两遍";② 传值方式:函数靠参数表传值;模块靠导线连端口——例化处的括号就是在"接线";③ 层级:顶层模块(Top-level Module)是直接接引脚的那层(我们的 pwm_breathe),它可以例化子模块,子模块再例化子模块——Vivado 左侧的 Hierarchy 面板就是这棵树。软件是调用栈,电路是积木。

parameter:每个实例一份自己的常数

ch01 你用过 parameter 缩小仿真规模,今天它当主角:#(.DIV(...)) 在例化的那一刻把常数"灌进"这一颗零件。2**23 是 lab01 的节奏,390_625 是下面的呼吸步进,434 是 ch06 的 UART 位节拍——同一份 tick_gen.v,三种性格。两个细节:

  • localparam 是"内部常数"($clog2 算出的位宽 W),外部改不了;parameter 才对外开放。该开的开,该关的关;
  • $clog2(DIV) 编译期自动算位宽,以后改 DIV 不用跟着改线宽——手写位宽迟早忘。

5 · 原理到电路:呼吸灯的结构图

图 2 · pwm_breathe 结构:tick 定步速,duty 是亮度目标,phase 是高速锯齿,比较器输出方波

对照代码读(labs/lab05-pwm/pwm_breathe.v,逐行注释版)。三段各司其职:载波相位每拍 +1 转圈(195.3kHz);亮度 duty 收到 step_tick 才动一步,三角波往返(0↔255 各 255 步,顶底各停一步);比较器每拍判决 phase < duty 输出方波。呼吸周期一笔账:

呼吸周期 = (255 亮步 + 255 暗步) × STEP_DIV ÷ 50MHz
         = 510 × 390625 × 20ns ≈ 4.0 s
警告 · 比较器的边界陷阱:一个字符的亮度差

assign led = (phase < duty); 写成 (phase <= duty) 会怎样? duty=0 时,前者恒假(全灭 ✓);后者在 phase==0 那一拍为真——占空比从 0/256 变成 1/256,"最暗档关不严"。就一个等号,暗房间里看得见微光。边界条件(duty=0、duty=255)永远值得单独问一句:极端值下,表达式还讲道理吗?

7 · 常见坑

坑现象解法
例化端口按位置连线 tick_gen u (clk, rst_n, tick);顺序一错 → 编译通过但行为诡异(最阴险的一类 bug)永远用命名关联 .clk(clk)
参数括号和端口括号写串tick_gen (.DIV(434), .clk(...)) 语法错参数在 #(),端口在 ():tick_gen #(.DIV(434)) u (...)
比较器用 <=最暗档微光(1/256 偷亮)用 <;0 档必须全灭
改 DIV 忘改计数器位宽位宽不够 → 计数器永远数不到 DIV-1,tick 失踪用 $clog2(DIV) 自动算
把 tick 接到组合逻辑再判边沿多此一举还引入毛刺风险tick 本身就是干净的 1 拍脉冲,直接当使能用

8 · 小结与自测

一条线:DRY 烦躁 → 抽出 tick_gen(parameter 化的零件)→ 例化进 led_blink2(和 cnt[23] 殊途同归)→ 例化进 pwm_breathe,三角波亮度喂给 PWM 比较器 → 呼吸灯。你第一次拥有了多模块工程:Vivado 左侧 Hierarchy 面板里那棵树,就是你的积木结构。tick_gen 请收好——ch06 它要换上 DIV=434 再出场。

C · 排错:同学的呼吸灯不亮,他的例化长这样,两处错误找出来:

tick_gen #(.STEP_DIV) u_step (clk, rst_n, step_tick);
答案(点开前先自己找)

B:见题面括号。B2:频闪,且占空比高时更明显(亮的更久,闪烁对比强)。
C:① 参数名错了——tick_gen 的参数叫 DIV,而且覆盖要给值:#(.DIV(390_625))(他写的 .STEP_DIV 既不是本模块的参数、又没给值);② 端口用了位置连接——这次恰好对,但这是"对了也是错"的写法,改成名命关联才算修好。顺带:参数名和顶层参数重名(STEP_DIV 是 pwm_breathe 的参数),说明他分不清"顶层的参数"和"零件的参数"——顶层的 STEP_DIV 应该在例化处传给零件的 DIV。
