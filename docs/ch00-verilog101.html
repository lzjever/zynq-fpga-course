1 · 为什么你一个字都看不懂

不是你的问题,是阅读方式的问题。你在大脑里"运行"这段代码——顺序执行、变量赋值、循环。但 Verilog 不是指令序列,是电路的描述文案。综合器读完它,制造出一块电路;那块电路没有"第 1 行、第 2 行"的概念,所有部分同时存在、同时工作、永远在线。

警告 · 最大的误区

把 Verilog 当 C 读,就像把建筑图纸当小说读——每个字都认识,完全不知道它在说什么。从下一节起,请换一副眼镜:读到的每一行,都要在脑子里"看见"一块硬件。

2 · 电路世界只有三种东西

整个数字电路世界,对你而言只需要三种零件。FPGA 里遍地都是这三种,几万到几十万个:

图 1 · 导线(组合传导)、寄存器(节拍存储)、时钟(统一节拍)——就这三种
知识 · 这就是"同步电路"

所有寄存器听同一个时钟的话,每个上升沿集体更新一次。两次上升沿之间,信号沿着导线稳定传播。整块芯片像一支踢正步的军队——步调一致,所以不会乱。这就是 FPGA 设计的第一定律"同步设计"。

3 · Verilog 只有两类句子

语法书厚得吓人,但描述电路的核心句子只有两种,分别对应上图的前两种零件:

句子造出什么语义例子
assign a = b & c;导线(组合逻辑)"a 那头,永久接在 b AND c 的输出上"接线,永不改变
always @(posedge clk)寄存器(时序逻辑)"每个时钟上升沿,做一次更新"节拍器驱动的存储
module ... endmodule元件封装一块电路的"外壳+引脚列表"类似软件的"类/函数签名"

没了。你此前看不懂的那段代码,只用了这三个语法点。

4 · 逐行解剖 led_blink.v

现在戴上电路眼镜,重读一遍。每一行右侧是它"造成"的硬件:

// ---------- 元件外壳:这块电路伸出 3 根引脚 ----------
module led_blink (
    input  wire clk,     // ① 一根进线:接 50MHz 晶振(芯片引脚 N18)
    input  wire rst_n,   // ② 一根进线:接按键(引脚 P14,按下=0V)
    output wire led      // ③ 一根出线:接 LED(引脚 R14)
);
// ---------- 一排寄存器:24 个 D 触发器并排 ----------
reg [23:0] cnt;                          // "cnt" 是 24 根线的一捆(24 位宽的寄存器组)

// ---------- 节拍器:下面这块电路在每周期的动作 ----------
always @(posedge clk) begin          // 每个 clk 上升沿,执行一次下面的"更新计划"
    if (!rst_n)                        // 按键按下?(导线上是 0V?)
        cnt <= 24'd0;                     // 计划A:下个节拍把 24 个触发器全清 0
    else
        cnt <= cnt + 1'd1;                // 计划B:下个节拍存入"当前值+1"
end
// 综合器把这块翻译成:24 个触发器 + 一个 24 位加法器,
// 加法器输出接到触发器的 D 端——一个每秒加 5000 万的电子计数器

// ---------- 一根导线:从计数器最高位,牵到 LED ----------
assign led = cnt[23];                   // led 引脚永久焊在 cnt 的第 23 位上,
                                        // 它是 1 就亮,是 0 就灭,全自动
endmodule
图 2 · led_blink.v 的真身:计数器芯片 + 一根导线 + LED,按键负责清零

5 · assign:一根导线的一生

assign led = cnt[23]; 这行最容易用软件思维误读:

软件误读 ❌电路真相 ✅
"执行赋值:把 cnt[23] 的当前值抄给 led"
(一次性动作,之后 led 与 cnt 无关)		"制造一根导线,一端焊在 cnt[23],另一端焊在 led"
(永久连接,cnt[23] 变,led 同时变,永远)

同理,assign sum = a + b; 不是"算一次加法",而是造一个加法器电路,输出永久跟踪 a+b。assign 造出来的所有东西统称组合逻辑——没有记忆,输入一变输出立刻跟着变。

6 · always:时钟节拍器

always @(posedge clk) 块里写的不是"循环",而是每个上升沿要做的一次"拍照计划":

  • 上升沿到来的一瞬间,所有 <= 左边的寄存器同时读入右边表达式的值;
  • 右边的表达式用的全部是拍照时刻之前的旧值——整块电路的更新是原子且并行的;
  • 两次节拍之间,寄存器保持不变,新值沿导线传播、稳定,等下一次节拍。
知识 · 为什么用 <= 而不是 =(非阻塞 vs 阻塞)

先记规则不纠结原理:always @(posedge clk) 块里,一律用 <=(非阻塞赋值)。它保证"全体寄存器读旧值、同步更新",这正是真实触发器的行为。用 = 会让仿真行为和真实电路不一致——这是新手第一大坑,记住规则即可,ch02(按键消抖)会展开:那里它是生死攸关的主角。

7 · 软件思维 vs 电路思维对照表

软件世界电路世界差异要点
变量(内存格子)reg(触发器)/ wire(导线)wire 没有存储,只是连接
顺序执行,一行接一行所有语句同时生效,并行运行代码行数 ≠ 执行顺序,只是"描述清单"
if/else 分支数据选择器(MUX)在两路信号里挑一路不是"走哪条路",是"两路都摆在那,挑哪路导通"
for 循环没有循环! 展开成 N 份并排电路for 只是"帮我复制粘贴 N 遍"的语法糖
函数调用模块例化(把子电路摆进大电路)"调用"出来的子电路永久存在,不是用完即走
print 调试仿真波形 / ILA 在线抓波形时间轴替代日志行,看的是"每根线的电压随时间变化"
程序启动比特流烧写(电路被"捏"成形)没有启动,电路从第一纳秒就在工作

8 · 新手三条铁律

铁律一 · 时序块里只用 <=

always @(posedge clk) 内一律非阻塞赋值 <=,组合逻辑(assign)随便。混用是 90% 诡异 bug 的来源。

铁律二 · 一个信号只在一个 always 里赋值

一根线只能有一个"驱动源"。两块 always 都写同一个寄存器 = 两只手抢一个方向盘,综合器直接报错(这是保护你)。

铁律三 · 画不出来就别写

写任何一段 Verilog 前,先能在纸上画出"寄存器+导线+门"的草图。画不出来的设计,写出来综合器也造不对。代码是电路的翻译,不是电路的源头。

9 · 动手:改三个数字做实验

改代码看现象,是最快的理解方式。基于 led_blink.v 做三个实验(每次只改一处):

#改动预测(先想再看答案)
1assign led = cnt[22];闪烁变快一倍(bit22 的方波频率是 bit23 的两倍)
2assign led = cnt[0];LED 以 25MHz 闪烁——肉眼根本看不见,看起来像"半亮"(示波器才能看清真相)
3reg [3:0] cnt;(只留 4 位计数器)每 0.32 微秒(16 拍)计满回绕一次,bit3 方波频率 = 50M ÷ 24 = 3.125MHz——又是"半亮",但比实验 2 慢
课堂练习 · 心跳的 3Hz 从哪来(先自己算,再展开对答案)

题目:led_blink.v 的 LED 焊在 cnt[23] 上,板上心跳约 3Hz——这个数是怎么从 50MHz 里长出来的?提示:先把三个容易混淆的量分开——翻转事件率、方波频率、LED 闪烁频率。算完再展开。

对答案:三个量,一个口诀
  • 翻转事件率:cnt[23] 每隔 223 个时钟翻转一次 → 50M ÷ 223 ≈ 5.96 次/秒
  • 方波频率:两次翻转构成一个完整周期(0→1→0)→ 50M ÷ 224 ≈ 2.98Hz
  • LED 闪烁频率:LED 通过 assign 直接焊在 cnt[23] 上——LED 的亮灭循环就是 cnt[23] 的方波周期 → 也是 2.98Hz(亮 0.168s、灭 0.168s)

口诀:第 N 位输出方波频率 = 时钟 ÷ 2N+1;bit23 → 50M/224 ≈ 3Hz。位号每减 1,频率翻倍——这就是"分频",FPGA 造时基的第一手法。

常见翻车:把"翻转率 ÷ 2"再除一次 2,得到 1.49Hz——那是把一个周期当两次、又除了一遍的重复计算。数字要动手验证,不管谁说的。
