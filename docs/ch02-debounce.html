CHAPTER 02

Lab02 按键消抖:先写后看

你以为按了一下按键?金属片其实弹了 20 毫秒。这一章,你第一次从零设计一件自己的电路。

钩子:金属不会说话,但它会弹

你按下 PL_KEY 的瞬间,按键里的金属簧片撞上触点——弹开,再撞上,再弹开,像一颗落地的小球,要蹦跶 5~20 毫秒才安分下来。这叫抖动(Bounce,机械触点的弹跳)。在这几毫秒里,你的电路看到的不是"一次按下",而是几十次快速的按-松-按-松。

软件工程师的条件反射是:sleep(20ms) 再读一次。但电路里没有 sleep——没有哪块硬件会"暂停世界等你醒来"。电路里表达时间的手段只有一样东西:数时钟拍。20 毫秒 = 50MHz × 20ms = 一百万拍。这就是本章全部的秘密。

还有一件事让这一章特别:这是全课程第一次"从零设计"。lab01 是改;这次是白纸一张,需求书在手,参考实现锁在折叠框里——先自己写,过三关,再看答案。身份转变从这一章开始:从"改代码的人"变成"设计电路的人"。

目标:读完这章你能

  1. 把"稳定保持 20ms"翻译成电路语言:"数满 100 万拍,中途抖回原电平就清零重数";
  2. 独立实现"稳定判定 + 边沿→单周期脉冲"两级结构,并用带随机抖动的测试台过三关;
  3. 用自己的话讲清非阻塞赋值 <= 的语义("全体读旧值,沿后齐更新")——兑现 ch00 埋下的承诺;
  4. 烧裸版和消抖版上板对比,按一次翻一次,50 次零失误。

归因预告 · 两个凶手,今天只审主犯

裸版乱翻有两个原因,别混为一谈:
主犯:机械抖动(毫秒级,人眼时间尺度)——按下瞬间的几十次弹跳,每个弹跳沿都被裸版放行成脉冲。这是今天要修的。
从犯:异步——P14 这根线不听 50MHz 时钟的号令,信号想什么时候翻就什么时候翻,采样时刻全凭运气。它安静得像只猫,但偶尔会咬人。今天先不修,下一章开庭重审(ch03 的开场就是这颗雷引爆)。

原理:把 20 毫秒变成一串数

时间滤波器:稳定才算数

思路一句话:信号想改变"判定电平"?可以,先连续稳定地保持 20ms(100 万拍)给我看。中途抖回原电平哪怕一拍,计时器清零重数。抖动的单次弹跳只有几微秒到几毫秒,凑不满 100 万拍——全被滤掉。手指真正按稳之后,计时器才能一鼓作气数满,判定才改口。

图 1 · 消抖 = 时间滤波器(时间轴不成比例:抖动区与稳定窗都做了压缩)

注意一件妙事:这个电路本质是一台只有两个状态的小机器(判定"松开"↔判定"按下"),转移条件是"稳定满 20ms"。ch06(UART 发送器)会给这种东西正名——状态机,并让它挑大梁。今天先不展开,记住这幅两格漫画即可。

第二级:从"电平"到"一拍脉冲"

判定电平 key_stable 一旦改口"按下",就会整整保持按下几十毫秒(你手指还按着呢)。但需求要的是一个单周期脉冲(Single-cycle Pulse,宽度恰好一个时钟拍)——像一次"点名",不是一段"状态"。从电平里抠出脉冲的手法叫边沿检测(Edge Detection),全课程最高频的惯用法,今天诞生:

reg key_stable_q;                          // key_stable 的"上一拍照片"
always @(posedge clk) key_stable_q <= key_stable;

assign tick = key_stable_q & ~key_stable;  // 上一拍是 1、这一拍是 0 → 1→0 沿,恰好一拍为高

这个 上一拍 & ~本拍(读作"刚才还是 1,现在已是 0")的模式,后面每一章都会再见面(松开沿就是反过来 ~q & d)。它产出的单周期脉冲有个行话名字:使能脉冲(Enable Pulse),昵称 tick——"这一拍允许你动一下"。全课程最重要的惯用法,没有之一。

兑现承诺 · 边沿检测为什么必须用 <=(ch00 埋的伏笔)

ch00 说过:时序块里一律用 <=,说好"ch02 展开"。这里就是生死攸关的地方,现在兑现:
非阻塞赋值 <= 的语义是"全体先读旧值,时钟沿之后一起更新"。所以 key_stable_q <= key_stable 在改判的那个时钟沿,读到的是改判前的旧值(还是 1);沿过后 key_stable 变 0 而 key_stable_q 还是 1——这一拍 tick 为高。下一拍照片更新,两个都成 0,tick 落下。恰好一拍,分毫不差。
如果这里用阻塞赋值 =:赋值立刻生效,"照片"瞬间变成新值,旧值永远拍不到——tick 要么出不来,要么仿真和综合行为分家,板上时对时错。ch00 铁律一的"为什么",到此结案。

知识 · 毛刺:组合逻辑的天然抖动

tick 是 assign(组合逻辑)算出来的线。毛刺(Glitch)指组合逻辑在输入翻转的瞬间、输出短暂地乱抖一下——门 delay 不齐造成的,真实电路里无法避免。为什么这里不怕?因为 tick 的两个输入都是触发器输出,只在时钟沿后变化;而它的下游(T 触发器)只在下一个时钟沿采样——毛刺活不到被采样的那一刻就稳了。记住设计纪律:组合逻辑的输出,永远只喂给时钟沿,不当时钟用。

参考实现逐行解剖(提示 3 展开后阅读)

闸门 · 没过三关别往下读

以下属于提示第 3 级内容。先自己写,过三关,再回来对照——顺序反了,这一章就白买了。

第一级:稳定判定(时间滤波器本体)

module debounce #(
    parameter STABLE_CYCLES = 1_000_000      // 20ms × 50MHz
)(
    input  wire clk,
    input  wire rst_n,
    input  wire key_n,     // 按下 = 0;名字带 _n 提醒"低有效"
    output wire tick
);
    reg        key_stable;  // 判定电平:1=松开,0=按下
    reg [19:0] cnt;          // 20 位:2^20=1_048_576 > 999_999,装得下

    always @(posedge clk) begin
        if (!rst_n) begin
            cnt        <= 20'd0;         // 复位:判"松开",计时归零
            key_stable <= 1'b1;
        end
        else if (key_n == key_stable)
            cnt <= 20'd0;                // 一致:不用计时。抖回原电平?清零重数!
        else if (cnt == STABLE_CYCLES - 1) begin
            key_stable <= key_n;         // 连续唱反调满 100 万拍:改判
            cnt        <= 20'd0;
        end
        else
            cnt <= cnt + 1'd1;            // 没数满:继续数
    end

读法:三条路的优先级从上到下——复位最高;key_n 与判定"一致"就归零待命;"不一致"才进入计时,计满改判。把这个 if 链和图 1 的波形对上:抖动区里 key_n 反复横跳,计时器数两三拍就被清一次零,永远够不着 100 万——这就是"被按在地上清零重数"。手指按稳后,100 万拍连续不一致,一鼓作气数满,改判。

两个细节值得抠:(a) 为什么比较 STABLE_CYCLES-1:cnt 从 0 起步,数到 999_999 恰好是第 100 万拍——数轴陷阱;(b) cnt 只在"不一致"期间才数,计数器本身就是滤波器,不需要额外的"抖动检测"电路。

第二级:边沿 → 单周期脉冲

    reg key_stable_q;
    always @(posedge clk) begin
        if (!rst_n) key_stable_q <= 1'b1;       // 复位:照片也是"松开"
        else        key_stable_q <= key_stable;  // 每拍拍照片(读旧值!)
    end

    assign tick = key_stable_q & ~key_stable; // 1→0 沿:恰好一拍为高
endmodule

原理节已拆透(<= 读旧值 → 恰好一拍),这里补一句工程习惯:照片寄存器和判定寄存器是两个 always 块——一根信号一个驱动源(ch00 铁律二)。想把两件事塞进一个 always 也能写对,但两个块各司其职,以后回炉改造(ch03 就要回炉)时不容易牵一发动全身。

顶层:key_toggle(消抖 + T 触发器)

module key_toggle (
    input wire clk,     // N18
    input wire key,     // P14(按下=0)——lab01 里它当复位,今天转正
    output reg led      // R14
);
    wire tick;
    debounce #(.STABLE_CYCLES(1_000_000)) u_debounce (   // 例化 + 拧真值参数
        .clk(clk), .rst_n(1'b1), .key_n(key), .tick(tick)
    );

    always @(posedge clk) if (tick) led <= ~led;  // T 触发器
endmodule

把 tick 变成"看得见"的东西,用的是翻转触发器(Toggle Flip-Flop,T 触发器):每收到一个脉冲,LED 翻转一次。它就是 tick 的"可见化仪表"——上游每按一次只放行一个脉冲,LED 才能做到按一次翻一次。消抖器的验收,最终由指尖裁决。

推演 · rst_n 为什么接常 1?上电会不会乱翻?

板上只有一颗 PL 按键,今天它是主角,没有第二颗给电路当复位(唯一的 RST 是整芯片复位,不能当信号用)。所以顶层把 rst_n 接死 1。那上电呢?FPGA 配置完成时所有触发器自动为 0:key_stable=0(判"按下"),而手指没按(物理是松开)——判定与事实不符,计时器开始数,20ms 后 key_stable 改判为 1。注意这是 0→1 的松开沿,tick 只报按下沿——LED 一个都不会误翻。推演一遍,放心上板(这也是"画不出来就别写"的微观版:想不清楚上电状态,就别让电路离开仿真)。

常见坑

坑 1 · 裸版"看起来也正常"?

抖动是概率现象:有的按键组合恰好在采样沿之间弹完,裸版偶尔也"按一次翻一次"。别被一次正常骗了——多按、快按、轻按。工程结论同理:"从来没错过"不等于"不会错",这句话下一章还会回来(而且是带着公式回来)。

坑 2 · 测试台的 20ms 变成 20ns(假通过)

ch01 预告的坑到了:测试台里写 #20_000_000 想表示 20ms,若 timescale 是 1ns/1ps,它确实等于 20ms——但如果你想仿真"缩小的稳定窗"却忘了同步改 DUT 参数,就会看到假 PASS/假 FAIL。本课测试台所有时长都用"时钟拍数"写(repeat (…) @(posedge clk)),换参数换板子都不用改——学走这个习惯。

坑 3 · tick 报了松开沿:按一次翻两次

如果你的边沿检测写成 ~key_stable_q & key_stable(0→1,松开沿也报),现象很直白:按一次 LED 翻两次(按下翻一次,松开又翻一次)。看到"翻两次"先查极性——需求书 R2 规定只报按下沿。

坑 4 · "数满就锁存"的误解

常见错误实现:计时器只管累加、不管中途一致不一致("累计满 100 万就改判")。抖动期间的碎片时间加起来也能凑满 100 万拍——毛刺被当成稳定按压,乱翻从正门回来。滤波器的灵魂是"连续"二字:抖回原电平哪怕一拍,清零重数。这也是自测 A2 的题。

小结

本章一句话

时间在硬件里的唯一形态是计数:20ms = 数满 100 万拍;"稳定"= 连续,抖回就清零。边沿检测"上一拍 & ~本拍"靠非阻塞读旧值,产出全课程最重要的惯用法——单周期脉冲 tick。你的第一件自产电路,三关全过,板上 50 次零失误:身份转变完成。

三档自测

A · 概念(用人话说)

1. "20 毫秒"在电路里是什么?用一句话说给软件工程师听。

2. 为什么消抖计时器要"抖回原电平就清零",而不是"累计时间数满就改判"?

看答案

1. 50MHz 时钟下的一百万拍——电路不懂毫秒,只懂数拍子。
2. 抖动期间信号反复横跳,碎片时间累加也能凑满窗口,毛刺会被误判成"稳定按压"。清零强制要求连续稳定,这才是滤波。

B · 预测(先猜,再跑)

1. 把 STABLE_CYCLES 从 1_000_000 改成 100(= 2µs),烧上板会怎样?

2. 按住按键 3 秒不放,tick 出几个?LED 翻几次?

看答案

1. 滤波窗口比很多抖动毛刺还短:间隔大于 2µs 的弹跳会被当成"稳定按压"放行——裸版的乱翻部分回归(概率性的,快速按最明显)。结论:窗口必须显著大于最长毛刺。
2. tick 恰好 1 个:改判只发生一次,之后信号与判定一致,计时器归零待命。LED 翻 1 次。(这正是验收三连的第三连。)

C · 排错(找 bug,说现象)

同学把边沿检测写成了一根"电平线",还振振有词:"按下期间输出 1,不是更直观吗?"

assign tick = ~key_stable;   // 按下期间,每拍都是 1

烧上板,按住按键:LED 呈现什么?为什么?

看答案

LED 半亮。因为下游 T 触发器每个时钟沿都看到"脉冲",LED 以 25MHz 翻转——人眼一平均,又是"半亮"!ch01 的悬案知识直接回收:数字电路没有半亮,只有高速翻转。电平是状态,脉冲是事件;把状态当事件用,下游就会每拍都"响应"。这就是边沿检测存在的理由。
