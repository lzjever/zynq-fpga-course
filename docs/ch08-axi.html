CHAPTER 08 · 纯仿真章

AXI 总线:和 ARM 说同一种话

你的 PL 至今是个聋子——今天给它装一扇 ARM 敲得开的门,先在仿真里请一个"假 ARM"来敲。

本章目标(可检验)
  1. 能说出总线解决什么问题(点对点连线的爆炸),AXI4-Lite 的适用场景(低速寄存器读写)
  2. 能背出五个通道(AR/R/AW/W/B)各送什么,复述握手两条铁律
  3. 能读懂 ~100 行的最小 AXI4-Lite 从机:写 = 存值,读 = 回值
  4. 能用 task 封装的 axi_write/axi_read 驱动从机,在波形里逐拍数出握手的成交时刻
  5. 能说清 Zynq GP 口的"AXI3 方言"坑是什么、两套预案分别是什么

1 · 钩子:让 ARM 伸手拨你的旋钮

从 lab01 到 lab07,你的电路一直在自说自话:呼吸自己呼吸,发报自己发报。P14 按键是它唯一听得见的输入——而隔壁那颗跑着 Debian 的 ARM,和你的电路明明躺在同一块硅片上,却谁也够不着谁。

把"够得着"翻译成具体需求,其实特别朴素:

愿望清单

让 ARM 能伸手拨你的旋钮——软件往某个地址写一个数,你的电路里就有一个寄存器变成这个数;软件再读这个地址,电路把现在的值报回去。有了这个,ARM 就能像调后台参数一样调你的 PWM 占空比、呼吸速度、任何参数。

这件事在软件世界你有现成的经验:多方设备互通,靠的是标准接口——HTTP、系统总线。硬件世界一模一样,这门规矩叫总线(Bus);FPGA 界事实上的普通话,是 ARM 家的 AXI。你可以把它理解成"FPGA 界的 HTTP":谁都听得懂,谁都得按它的格式说话。你写的从机(slave)就是一个最小的"Web 服务",寄存器就是它的 API。

2 · AXI 家族:一分钟认亲

AXI 全称高级可扩展接口(Advanced eXtensible Interface, AXI),是 AMBA(Advanced Microcontroller Bus Architecture,高级微控制器总线架构)家族的第三代成员。你只需要认识三兄弟中的两个:

成员一句话定位本课程何时用
AXI4(完整版)带突发的全功能读写,高性能数据搬运(DDR、视频流)不教(进阶路线图)
AXI4-Lite(轻量版)无突发、一次一笔的寄存器读写——就是"拨旋钮"这个需求的精确对位本章主角
AXI4-Stream(流版)无地址的纯数据流,视频/网络包专用只在路线图提名字

用 HTTP 类比:AXI4 像支持 keep-alive 和分块传输的完整 HTTP,AXI4-Lite 像"一次一个请求"的极简版——对你的寄存器旋钮来说,极简版刚刚好。

3 · 五个通道:一张柜台窗口图

AXI 的所有交互拆成五个独立通道(channel),每个通道都是一根独立的"传单槽"。方向以谁发起分:发起方叫主机(Master),应答方叫从机(Slave)。

写一笔要用三个通道:AW(说清往哪写)、W(数据本体)、B(从机的回执)。读一笔用两个:AR(说清读哪里)、R(数据 + 回执一起回来)。

注意一个反直觉:W 是"主机→从机"的数据线,但 B 是"从机→主机"的回执线——写一笔也有回应,和 HTTP 的 POST 有 response 一模一样。而 R 把数据和回执合并在一个通道,像 GET 的响应体。

通道方向载荷HTTP 类比
AW(Write Address)主→从地址、长度POST 的 URL
W(Write Data)主→从数据本体POST 的 body
B(Write Response)从→主响应码(OKAY/ERROR)POST 的状态码
AR(Read Address)主→从地址GET 的 URL
R(Read Data)从→主数据 + 响应码GET 的响应体 + 状态码

4 · 握手:valid/ready,两个文明人的抬杠仪式

五个通道里的每一个,都靠同一套两线协议成交——这是 AXI 全部优雅的来源:

  • VALID(发起方举):"我的单子已经放槽里了,有效。"
  • READY(接收方举):"我这边准备好了,随时能收。"

成交规则一条:同一时钟上升沿,两根线同时为 1,这一笔单子成交,下一拍各自收线。谁先举、谁后举都无所谓——VALID 可以举着等 READY(图 4 左半),READY 也可以先举着等 VALID。

图 4 · VALID 先举、READY 后到的握手:成交发生在"两线同高"的那个上升沿(绿框),之后双方各自收线。

握手两条铁律(违反 = 死锁或丢数)

① VALID 一旦举起,不得撤销,直到成交。为什么?接收方可能在你举 VALID 的同一拍就"开始消费"了——比如把数据锁进寄存器。你单方面撤单,它等你、你等它的新单,两边永远互相等:这就是硬件版的死锁(deadlock)。

② VALID 举起后,载荷(地址/数据)不得改变。单子递出去就不能再涂改,道理同上。

(READY 没有这个限制:接收方可以随时举、随时放——它是"被动方",撤回的只是"我现在方便"这个状态。)

知识 · AXI 握手本质也是状态机

上一章你刚写完 UART 的有限状态机。回头看这个从机:aw_seen/w_seen → write_fire → bvalid,就是"等地址 → 等数据 → 回执"的三态小机器。ch07 的技能直接续上——你不是在学新东西,是在换一种用途用旧技能。

5 · 寄存器映射:旋钮的编号表

从机对外其实就是一张极短的表,叫寄存器映射(Register Map)——哪个偏移地址对应哪个旋钮:

偏移名字读/写含义
0x00REG0读写唯一的旋钮:写 = 存值,读 = 回值(本章)
0x04——lab09 会加:SPEED 呼吸速度寄存器

"地址映射"(Address Map)是同一件事在系统层面的说法:每个从机在整个地址空间里占一段。Zynq 上,ARM 侧伸进 PL(可编程逻辑)的通用端口(General Purpose Port, GP0)给你的从机划的窗口从 0x4000_0000 开始——所以 ch09 里你会看到 devmem 0x40000000 这一枪,打中的就是偏移 0x00 的这个寄存器。地址译码(address decode)是从机内部的事:拿地址低几位选寄存器,本章单寄存器版先不译(所有地址都落到 REG0),lab09 的双寄存器版会用一个 case 补上。

6 · 动手一:从机逐段解剖(阅读实验,不是从零写)

本章的从机是阅读材料——AXI 的坑在握手细节里,第一次就让你从零写等于让你背规范。打开 labs/lab08-axi/axi_lite_slave.v,三个部分:

接口:把五通道原样声明成端口

module axi_lite_slave #(
    parameter ADDR_W = 4
)(
    input  wire              aclk,      // 总线时钟(TB 给;板上来自 FCLK0)
    input  wire              aresetn,   // 低有效复位,AXI 惯例带 n
    // 写地址通道 AW
    input  wire [ADDR_W-1:0] s_axi_awaddr,
    input  wire              s_axi_awvalid,
    output wire              s_axi_awready,
    // ……W / B / AR / R 四个通道同理,完整版见 lab 文件
    output wire [31:0]       knob       // ★ 寄存器的影子:旋钮手柄,给外电路抓
);

没有函数、没有调用——从机的"API"就是这一排端口。命名 S_AXI_* 是 Xilinx 惯例(S = Slave 侧),ch09 它们会原封不动连到 PS7 的 MAXIGP0*(M = Master 侧;IP 封装名带下划线写作 M_AXI_GP0_*,PS7 原语实名不带)。

写路径:两个通道各自记账,到齐才落寄存器

reg        aw_seen, w_seen;          // 地址到了吗 / 数据到了吗(各自成交拍置位)
reg [31:0] wbuf;                   // W 成交拍锁存的数据(必须锁!见下方坑 3)
reg [31:0] reg0;                   // ★ 旋钮本体
wire write_fire = aw_seen && w_seen; // 到齐 → 这拍落寄存器

assign s_axi_awready = !aw_seen;     // ready 策略:空闲时永远欢迎
assign s_axi_wready  = !w_seen;

always @(posedge aclk) begin
    if (!aresetn) begin ... end
    else begin
        if (s_axi_awvalid && s_axi_awready) begin aw_seen <= 1'b1; awbuf <= s_axi_awaddr; end
        if (s_axi_wvalid  && s_axi_wready ) begin w_seen  <= 1'b1; wbuf  <= s_axi_wdata;  end
        if (write_fire) begin
            reg0    <= wbuf;             // ← 拨旋钮的时刻:写 = 存值
            aw_seen <= 1'b0;  w_seen <= 1'b0;
            bvalid  <= 1'b1;            // 举回执(B 通道)
        end
        if (bvalid && s_axi_bready) bvalid <= 1'b0;  // 回执成交才放下(铁律①)
    end
end

对照柜台图读一遍:AW、W 两个传单槽各自握手(第 4-5 行),谁先成交都行;两个 seen 都置位后 write_fire,寄存器落值、B 通道举回执。回执本身又是一次握手——bvalid 举着等主机的 bready,成交才放。一笔写 = 三次握手。

读路径:一次握手,数据保持到成交

assign s_axi_arready = !s_axi_rvalid;      // 上一笔没回完,不接新单
always @(posedge aclk) begin
    if (!aresetn) begin ... end
    else if (s_axi_arvalid && s_axi_arready) begin
        rvalid <= 1'b1;
        rdata  <= reg0;                    // ← 读 = 回值:把现值端出去
    end
    else if (rvalid && s_axi_rready)
        rvalid <= 1'b0;                     // 成交后放下
end
assign knob = reg0;                        // 旋钮手柄:值一变,外电路立刻看得见

7 · 动手二:TB 假扮 ARM

从机的对方叫主机——本章由 testbench 出演。核心动作:把"一次完整的 AXI 写/读"封进两个 task,以后调用它们就像调函数:

// 写一笔 ≈ devmem 0x40000000 32 0x55
task axi_write(input [3:0] addr, input [31:0] data);
    reg aw_done, w_done;
    begin
        @(posedge aclk);
        s_axi_awvalid <= 1'b1; s_axi_awaddr <= addr;   // 举 AW + W(同拍举,协议也允许先后)
        s_axi_wvalid  <= 1'b1; s_axi_wdata  <= data;
        s_axi_bready  <= 1'b1;
        while (!aw_done || !w_done) begin      // 各通道分别等成交
            @(posedge aclk);
            if (s_axi_awvalid && s_axi_awready) aw_done = 1'b1;
            if (s_axi_wvalid  && s_axi_wready ) w_done  = 1'b1;
            if (aw_done) s_axi_awvalid <= 1'b0;  // 成交拍之后才准撤(铁律①)
            if (w_done)  s_axi_wvalid  <= 1'b0;
        end
        while (s_axi_bvalid !== 1'b1) @(posedge aclk); // 等回执
        s_axi_bready <= 1'b0;
    end
endtask

读的 axi_read 对称:举 AR → 等 R 成交 → 收走 rdata(完整代码在 tb_axi_slave.v)。剧本主菜只有三行——这就是 ch09 里真 ARM 视角的预演,对软件来说,总线访问缩水成"往一个地址写了个数":

axi_write(4'h0, 32'h0000_0055);   // 写 0x55 进寄存器
axi_read (4'h0, rdata);           // 读回来
// 检查:rdata == 0x55?knob == 0x55?→ PASS/FAIL 自动记分
知识 · task 里的采样时机(防"TB 与 DUT 同源"盲区)

task 在 @(posedge aclk) 醒来后立刻用阻塞读读握手线。因为 DUT 全用 <= 更新,同一时刻读到的必然是"这一沿之前"的稳定值——恰好就是成交判定条件。ch07 讲过"TB 的采样假设要独立于 DUT",这里是同一件事的握手版。另外注意 TB 是唯一允许用 =、while、# 的地方——它本来就是"写给仿真器的软件"(ch01)。

波形里做一次"数拍子"练习——找到第一笔写,依次标出:

  1. AW 成交拍(awvalid && awready 同高的那个沿)
  2. W 成交拍(通常同拍)
  3. knob 跳到 0x55 的拍(write_fire,比上一步晚一拍——因为 seen 要先置位)
  4. B 回执成交拍(bvalid && bready)

这四拍的先后顺序,就是"ARM 写你一个寄存器"在时间上的全展开。看懂了它,ch09 的 devmem 对你就只是一行压缩。

10 · 那条沟:Zynq 的 GP 口说的是"AXI3 方言"

一切美好之下有一件必须如实告诉你:ch09 要把你的 AXI4-Lite 从机直连到 ARM 侧的通用端口 GP0 上,而按官方技术手册 UG585,Zynq-7000 的 GP 口说的是 AXI3——AXI 的上一版方言,比 AXI4 多了几个信号(事务 ID、突发长度字段等),和我们学的 AXI4-Lite 并不完全同名同规格。

好消息是:devmem 单字访问是"单拍、无突发"的事务,AXI3 单拍传输的行为与 AXI4-Lite 高度重合,从机侧对 AXI3 独有信号置之不理即可——大概率直连就能工作。但"大概率"不是工程答案:

待实测门(全书三项"待实测"之一)

开写 ch09 前必须实测:AXI4-Lite 从机直挂 GP0,是否被容忍。两套预案都备好了,实测后二选一:

方案内容代价
甲 · 免桥直连(首选)GP0 的 AXI3 单拍 ↔ 我们的 Lite 从机,从机忽略 ID/突发类信号0 个 IP,顶层最简
乙 · 垫 AXI Interconnect用免费的 AXI Interconnect IP 做协议转换(AXI3 主侧 ↔ AXI4-Lite 从侧),create_ip 全脚本生成,不需要进 Block Design多一个 IP,资源 +几百 LUT,顶层多一层连线

本课和 lab09 的代码按方案甲写;若实测落在乙,lab09 的 build.tcl 里预留了注释开关(见其 README)。

预告 · PS7 直例化,不进 Block Design

行业里连 PS 和 PL 常用图形化的 Block Design。本课程反其道:ch09 直接在 Verilog 里例化 PS7 原语——像例化一个普通模块那样把 GP0 的几十根线和 FCLK 时钟接出来。对你这个命令行重度用户,这是更诚实的一条路:没有黑盒向导,每一根线都看得见。

11 · 常见坑

坑 1 · XSIM 不查协议

仿真器只仿真你写的逻辑,不检查你是否遵守 AXI 规范。你把 VALID 举起来又撤销,仿真多半照跑不误;上了真总线可能死锁。规范意识要自己带——铁律两条贴在显示器上。

坑 2 · 只等了一个通道就开始写寄存器

AW 和 W 是两个独立握手:可能地址先到、数据后到(常见),也可能反过来。谁先谁后不确定,所以必须 aw_seen && w_seen 都置位才 fire。只等 W 不等 AW,地址还没到就落寄存器,读回来一看全对(因为单寄存器不译码),一上双寄存器设计立刻写串门。

坑 3 · 不锁存就晚用

W 成交后主机下一拍可能就换数据了。如果 write_fire 隔了一拍才发生,而你直接用 s_axi_wdata,用的已经是别人的下一笔。所以成交拍必须锁进 wbuf——这是从机代码里最容易被"看起来对"骗过去的一个细节。

坑 4 · 回执不等成交就放下

bvalid/rvalid 的放下条件必须是 && ready,不能"举一拍就收"。主机可能忙,READY 迟迟不来——你先撤了,它以为你还在,又等回去:死锁。

12 · 小结

  • 总线 = 多方互通的标准前台;AXI4-Lite = 一次一笔的寄存器读写,正对"拨旋钮"需求
  • 五通道 AW/W/B(写)+ AR/R(读);每通道一套 valid/ready 握手,同拍同高成交
  • 铁律:VALID 举起不得撤销、载荷不得变;READY 随便
  • 最小从机 = 一个寄存器 + "等地址、等数据、回执"的小状态机;写 = 存值,读 = 回值
  • TB 用 task 假扮主机,封装后一行调用——这正是 ch09 真 ARM(devmem)的视角
  • GP0 说 AXI3:两案备好(直连 / 垫 Interconnect),实测门后二选一

13 · 三档自测

A(概念复述)· 用"人话一句话"说清:为什么 VALID 一旦举起就不能撤?(提示:站在接收方角度想它什么时候开始消费)

B(预测题)· 把 TB 里的 s_axi_bready 从"每笔写时才举"改成复位后就永远为 1,其余不动。先猜:波形上 B 通道的握手会少几拍?PASS/FAIL 结果会变吗?

C(排错题)· 同学把从机改成两寄存器版,地址译码写成 case (awaddr) 全比较 4'h0 和 4'h4,却忘了 default 分支。他写 0x00、0x04 都正常,为什么说这颗雷是"下一个读 0x8 的人踩"?

展开答案(先自己答,再对)

A:接收方可能在 VALID 举起的那一拍就把数据锁走/开始处理,它没法预知你会撤;你撤了它还举着 READY 等你,你等它的新单——互相等,死锁。所以规矩是:单子递出去就作数,直到成交。

B:B 通道 bvalid 与 bready 本来就是"从机举、主机在写期间举",bready 恒 1 时成交拍不变(还是 bvalid 举起后的第一个沿),波形几乎不变,PASS 不变。考察点:READY 先举后举都合法,成交只看"同拍同高"。

C:XSIM/综合器对不完整 case 且无 default 的时序逻辑,通常保持原值(latch 倾向)——写 0x8 时没有任何分支命中,寄存器维持旧值"看起来没反应";但不同工具/不同写法下行为未定义,规范做法是 default 里落一个默认值或返回错误响应。地址译码永远写全分支。
