CHAPTER 07 · LAB 06

UART 发送器:时间是编码

把一个字节变成时间轴上的 0 和 1 —— 你的第一个正式状态机,和一次"用眼睛当接收器"的行为艺术。

0 · 开场:会呼吸,但不会说话

到目前为止,你和这块板子的全部交流方式,本质上是同一种:看灯。闪烁是灯,呼吸还是灯——电路一直在"给你表演",但从没"对你说过话"。今天我们让它开口:电路世界最古老、至今没死的社交协议——通用异步收发传输器(Universal Asynchronous Receiver/Transmitter, UART),你调 Debian 用的那根 115200 串口线,每个字节怎么变成 0 和 1 在线上跑,今天从发送端亲手造一个。但有个坏消息必须第三句就摊牌:板上那颗 CH340(USB 转串口芯片)焊死在 PS 侧,接的是 ARM 的 UART——你在 PL 里造的发送器,这根线物理上到不了电脑终端。所以"怎么看见自己发的东西"是今天要和"怎么造"一起解决的问题,而解决方案会漂亮得像个恶作剧:把波特率调到每秒 2 个位,用 5 秒钟,在 LED 上用肉眼读出一整个字节。

1 · 本章目标

  1. 能凭记忆画出 UART 帧格式(1 起始位 + 8 数据位低位先行 + 1 停止位),并算出 115200 波特下一位宽 = 8.68µs = 434 个 50MHz 时钟;
  2. 能说出状态机解决的到底是"什么问题"(电路需要"记住自己干到哪一步了"),并把状态转移图的每条弧逐条翻译成 Verilog;
  3. 能在仿真里让测试台当接收器,控制台打印出 Hello PL!,位序/位宽双核对;
  4. 能在板上完成参数三级跳:同一份代码,2 波特肉眼读帧 → 115200 肉眼失效 → ILA 波形窗逐位解出 'H';
  5. 能用 ILA 游标量出一个位的宽度,验证波特率真的对(这是自环回路查不出来的东西,下一章见分晓)。
知识 · 本章投资预算

预计 3–4 小时:原理 + 仿真约一半,板上三级跳 + ILA 约一半。方差小——本章是教学式跟做,状态机的"近迁移自写"考验留给下一章。

2 · 原理一:帧——UART 的时间语法

UART 的"异步"两个字是关键词:两台设备之间没有时钟线。没有节拍器,接收方怎么知道哪是哪一位?答案是——靠事先约定的时间。双方说好"每秒打 115200 个位"(波特率,Baud Rate:每秒传输的位个数),然后发送方把每个字节包装成一个帧(Frame):一帧 10 个位,从一次"由高到低"的跳水动作开始,以一段"回到高"的休止符结束。

图 1 · 一帧 'H'(0x48)。起点是那个醒目的高→低跳水(起始位),接收方就靠它对表;8 个数据位低位先行;停止位拉高回到空闲。本图坐标即下一节 FSM 要逐位复现的时间表。

三个规矩值得逐条咬死,因为每一个都会在板上变成现象:

  • 起始位(Start Bit):线空闲时恒为 1。发送方拉低一个位时间 = "预备——"。接收方什么同步信号都没有,全靠盯住这记下降沿对表——所以它必须足够醒目,而且之前线路必须干净地保持 1。
  • 最低有效位先行(Least Significant Bit First, LSB First):8 个数据位从 byte 的第 0 位(最低位)开始发。这是历史习惯,不是道理,但双方必须一致——反着发,同样的波形会解出完全不同的字节('H' 会变成 0x12)。
  • 停止位(Stop Bit):拉高至少一个位时间 = "完"。它同时把线路还原成空闲态 1,好让下一帧的起始沿干干净净。

合起来写成黑话叫 8N1:8 数据位、无校验(No parity)、1 停止位——串口世界的"你好"。加上波特率(如 115200-8N1),就是一份完整的通信合同。波特率本质:它不是一个时钟,是一句约定的话——"我们每 8.68µs 换一位"。谁守约谁就能被听懂,这一点等会儿会被我们恶意利用。

3 · 原理二:FSM——电路的"进度感"

发一帧要按顺序干四件事:拉低、逐位发、拉高、回空闲。顺序!这对软件是本能,对电路是个新问题——你至今写过的所有电路(计数器、消抖器、PWM)都是"每拍干一模一样的事",不需要知道"自己是第几步"。而发送器必须记住"我发到第几位了"。有限状态机(Finite State Machine, FSM)就是干这个的:一组触发器存"现在第几步"(状态),一段组合逻辑算"下一步去哪"(转移),输出由当前状态决定。它不是新零件,只是把"寄存器 + 逻辑"按一种特别有用的方式组织起来——从此它将承包你后面见到的所有协议(UART 接收、AXI 握手、全是它)。

本课的状态机取三态,对应帧的三段:

图 2 · 发送状态机:三个圈 = 帧的三段;每条弧 = 一个跳转条件。把这张图和代码逐弧对照,是本课最重要的练习——ch00 铁律三"画不出来就别写"在此正式回收:先有图,再有代码。
知识 · 状态机的两段式写法(全书模板)

状态机代码固定两段:时序段——一排触发器,每拍把 next_state 存进 state,顺带做各状态的数据动作(移位、计数、驱动 tx);组合段——一段纯逻辑,按"当前状态 + 输入"算 next_state。状态用 localparam 编号(S_IDLE=0…),不写魔数。这个骨架你将写很多遍,直到不用想。

4 · 动手一:发送器代码(逐弧映射)

完整文件在 labs/lab06-uart-tx/uart_tx.v(逐行注释版),外加 key_pulse.v——就是 Lab02 消抖器 + Lab03 打两拍的老组合,把 P14 变成一个"发射按钮":按一次,出一帧。两块旧知识第一次原样复用,这就是课程的复利。核心骨架如下(节选):

// ---- 位内节拍:数满 BAUD_DIV 个时钟 = 一个位时间 ----
if (baud_cnt == BAUD_DIV-1) baud_cnt <= 0;
else               baud_cnt <= baud_cnt + 1'd1;

case (state_r)
  S_IDLE: begin
      tx <= 1'b1;                       // 空闲电平(协议规定)
      if (start) begin
          shifter <= data;  bit_cnt_r <= 0;  // 装弹:字节进移位寄存器
          tx <= 1'b0;                       // ← 起始位:拉低!对应图2第一条弧
      end
  end
  S_SEND: if (baud_cnt == BAUD_DIV-1) begin
      if (bit_cnt_r == 8)  tx <= 1'b1;   // 数据发完 → 停止位,对应图2第二条弧
      else begin
          shifter <= {1'b0, shifter[7:1]};      // 右移:下一位挪到最低位
          tx <= shifter[0];                  // LSB 先行,先发最低位
          bit_cnt_r <= bit_cnt_r + 1'd1;
      end
  end                                   // 位没数满:不赋值,tx 自动保持(图2的自环弧)
  S_STOP: tx <= 1'b1;                           // 停止位保持高,数满回 IDLE
endcase

// ---- 组合段:次态逻辑,图2的每条弧各占一行 ----
S_IDLE: next_state = start ? S_SEND : S_IDLE;
S_SEND: next_state = (baud_cnt==BAUD_DIV-1 && bit_cnt_r==8) ? S_STOP : S_SEND;
S_STOP: next_state = (baud_cnt==BAUD_DIV-1) ? S_IDLE : S_STOP;

对照着看:状态图上每条弧,在组合段里恰好一个条件表达式;每个圈里"持续做的事",在时序段里恰好一个分支。这层机械对应就是状态机的全部——没有玄学。shifter 是移位寄存器(Shift Register):并行进、串行出,把并排放着的 8 个位一位一位挤到线上,它是所有串行协议的心脏。

知识 · BAUD_DIV 的算术,与 $clog2 的小聪明

一个位 = 波特率分之一秒 = 50_000_000 ÷ 波特率 个时钟:115200 → 434(实际误差 +0.006%,协议容忍 ±2%,宽裕);9600 → 5208;2 波特 → 25_000_000(一个位整整半秒)。计数器位宽用 $clog2(BAUD_DIV) 自动算——434 要 9 位,25_000_000 要 25 位,参数一改位宽自己长,这就是三级跳不用改行的原因。

5 · 动手二:仿真先行——让 TB 当接收器

上板之前先仿真,这次 TB 的角色特别讲究:它自己就是一个用软件写的 UART 接收器——等下降沿、按位宽走到每个位的正中间采样、按 LSB 拼回字节。跑起来:

# labs/lab06-uart-tx/ 下
vivado -mode batch -source sim.tcl

控制台最后应该滚出:

Hello PL!
--- PASS (10/10 字节,位序/位宽/起停全对) ---

硬件在发,软件在收,两边各写各的——这一刻你完成了一次真正的通信,虽然双方都在同一台电脑上。注意一个刻意的细节:TB 的位宽是它自己声明的常数,并不引用 DUT 的 BAUD_DIV。发送器波特率写错了,TB 会采错位置、打出乱码,bug 当场现形——验证方不能和被验方共用同一份假设,这是比本课代码更值钱的习惯。

6 · 板上现象:肉眼 UART 与参数三级跳

现在解决开场埋的问题:PL 的 TX 到不了电脑,那谁当接收器?你的眼睛。顶层 lab06_top.v 干了一件恶作剧的事:把 tx 线直接接到 R14 LED 上。然后利用波特率"只是一句约定"的本质,恶意违约——把约改成每秒 2 个位:

# 肉眼版:2 波特(一个位 0.5 秒)
vivado -mode batch -source build.tcl -tclargs eye
vivado -mode batch -source program.tcl   # 烧写前先 pkill -f openocd

烧完先别按键——LED 常亮?对,tx 空闲态 = 1,协议规定。按一下 PL_KEY,然后盯着 LED 数五秒,对照下表(按行读,每行 0.5 秒):

LED灭亮灭亮灭亮起后常亮

读出来的数据位序列(LSB 起):0001 0010 → 倒着拼 = 0100 1000 = 0x48 = 'H'。你的视网膜刚刚扮演了一台 2 波特的串口终端。同一个人眼,同一份代码,现在逐级换合同(build.tcl 的 -tclargs 换一个词,源码零改动):

成果 · parameter 的三级跳(全书主题第 2 跳)

第 1 跳在 ch01:仿真跑不动 1600 万周期,把计数器参数改小,压缩时间;第 2 跳是今天:把波特率参数改大,放大时间到肉眼可读;第 3 跳在 ch09:换主频参数,电路从 N18 时钟搬到 ARM 送来的 FCLK——同一份代码,时间尺度随意伸缩。parameter 不是语法糖,是你对"时间"的定价权。

7 · ILA 主验证:抓一帧真的 115200

real 模式下肉眼缴械,但电路每秒能打 115200 个位——我们给它配一台显微镜。集成逻辑分析仪(Integrated Logic Analyzer, ILA):一个由 Vivado 生成的 IP 核,综合后住进你的芯片里,盯着你指定的内部信号,按系统时钟不停记录、循环覆盖;条件满足(触发,Trigger)时冻结一小段历史,通过 JTAG 上传到波形窗。仿真看的是"理论世界",ILA 看的是你这块硅片上真实发生的事——综合、布局、布线之后的真波形。

ila 模式一条龙(触发按钮还是 PL_KEY,只是这次按完去电脑上看,而不是盯 LED):

vivado -mode batch -source build.tcl -tclargs ila
vivado -mode batch -source program.tcl
# 然后开 GUI:Hardware Manager → Open Target → Add ILA core
警告 · ILA 当天必撞的坑:JTAG 互杀

ILA 走 JTAG,而 JTAG 上那颗 FT232H 是独占的——你调 Debian 时开过的 OpenOCD 还在后台的话,hw_server 起不来,Hardware Manager 会"找不到目标"。开 Vivado 硬件管理器之前,先执行 pkill -f openocd;反过来要用 OpenOCD 时杀 hw_server。口诀进附录 C,今天先肌肉记忆一次。

抓帧五步:① 触发条件设 tx == 0(线空闲恒 1,拉低即起始位,条件干脆);② 点 Run Trigger(武装);③ 按一下 PL_KEY;④ 波形冻结,tx 线上就是那 86.8µs 的一帧;⑤ 放大读位,配合 bit_cnt/state 两根总线看状态机脚步。然后做本课的保留节目:

练习 · 游标量位宽(自环的盲区,只有它能救)

波形窗里放两根游标,卡在 tx 相邻两次电平变化的沿上,读出时间差。应为 8680ns ± 20ns(434 × 20ns,容 1 个时钟的量化误差)。这就是"用测量验证波特率"——记住这个动作,下一章自环实验有个隐蔽盲区:TX 和 RX 用同一个 BAUD_DIV,错也错得整整齐齐,回环永远自洽,波特率错了它查不出来。到时候,唯一说真话的就是这两根游标。

知识 · 免费档的 ILA 限额,如实交代

免费档(安装界面名 Vivado ML Standard,授权页称 Basic)限 1 个 ILA 核、每核 5 个探针(Probe,被测信号;多位总线算 1 个)。本设计探针 5 个用满:tx、busy、tick、bit_cnt[3:0]、state[1:0]——其中解一帧其实只要 tx/busy/bit_cnt/state 四个,第 5 个名额给了 tick(按键脉冲),它是个好触发词:按一次抓一次。采样深度(Sample Depth)按 8192 配:115200 一帧 = 4340 点,8192 能装下一帧半,够用。待实测注记:免费档深度上限以 2026.1 实机为准;万一 8192 不可用,方向是升波特率(921600 → 一帧仅 542 点)而不是降——采样率固定 50MHz,波特率越低一帧点数越多,降波特率只会更装不下。

9 · 小结

  • UART 异步的本质:没有时钟线,时间本身就是编码;波特率是一句双方共享的约定话。
  • 一帧 = 起始(0)+ 8 数据(LSB 先行)+ 停止(1);空闲恒 1;下降沿是接收方唯一的时间基准。
  • FSM = "会记进度的电路":状态寄存器 + 次态组合逻辑;状态图每条弧 ↔ 代码每行条件,图先于代码。
  • parameter 三级跳第 2 跳:BAUD_DIV 一改,2 波特给眼睛、115200 给 ILA,代码零改动。
  • ILA = 住进芯片的显微镜;免费档 5 探针恰好够;游标量位宽是验证波特率的唯一板上手段。
