A.1 板卡档案:一表流

主角:微相科技(MicroPhase)Z7-Nano R20。它是一颗片上系统(System on a Chip, SoC)——Zynq XC7Z020-2CLG400,体内塞了两个世界:跑 Debian 的处理系统(Processing System, PS,双核 ARM Cortex-A9)和你在写的可编程逻辑(Programmable Logic, PL,Artix-7 级 FPGA)。本课程在 PL 里造电路,到 ch09 才让两边握手。

项目规格 / 实况对课程意味着什么
芯片 Zynq XC7Z020-2CLG400(速度等级 -2,400 脚封装) build.tcl 里 part 写 xc7z020clg400-2,等级写错时序全变
内存 DDR3(双倍速率三代同步内存,Double Data Rate 3, DDR3)512MB,归 PS 管 PL 课程不碰;PS 侧跑 Debian 全靠它

供电 两个 type-C 口任一可供电(OR 二极管合路) 只插 JTAG 口一根线也能烧写(A.3)
知识框:为什么引脚表里全是 LVCMOS33

PL 的引脚按 bank 分组,同组引脚共享一个供电脚 VCCO(输出电压由它决定)。本板排针和核心三脚所在的 bank 34 / bank 35,VCCO 都接 3.3V(已从原理图核实)——所以这一页所有 IO 的电气标准都写 LVCMOS33(3.3V 低压 CMOS 电平标准,Low-Voltage CMOS 33)。约束文件里 IOSTANDARD 与此一致,写错标准轻则报设计规则检查(Design Rule Check, DRC)错误,重则电平不匹配。

A.2 接口辨认:两个 type-C、两个 RJ45、一组跳线

板上有几对"长得一样、分工不同"的接口,新手坑几乎都出在这里。总原则:按功能认口,别按"插上亮不亮"认口。

接口怎么认插错的症状
type-C ×2 丝印「UART」口里是 CH340E(主机 lsusb 认 1a86);丝印「JTAG」口里是 FT232H(认 0403:6014) 插 UART 口永远连不上 JTAG,插 JTAG 口永远没串口——两边都能供电,所以"能开机"不代表"插对口"
RJ45 ×2 PS ETH(靠近哪侧以板面丝印为准)才是 Debian 的 eth0;PL ETH 无驱动 电脑侧有链路、板上 eth0 无载波(NO-CARRIER)= 插到 PL ETH 了,换口即愈
启动跳线 多位拨码开关,档位以板面丝印为准;课程全程放 SD 档 不在 SD 档时 BootROM 空等,串口全静默——最像"板子坏了"的假死

跳线档位不用猜,芯片里有答案:启动模式寄存器 BOOT_MODE 挂在系统级控制寄存器(System-Level Control Registers, SLCR)空间,地址 0xF800025C,JTAG 一条命令读回——读回 5 即 SD 档。寄存器不会撒谎,跳线不会伪装:

# 主机:OpenOCD 读 BOOT_MODE(三板斧见姊妹手册第 6 章;cfg = 其仓库 openocd-z7nano.cfg)
openocd -f openocd-z7nano.cfg -c "init" -c "halt" -c "mdw 0xF800025C" -c "resume" -c "shutdown"
# 输出 0x00000005 = SD 档;不是 5 先去掰跳线,别的都不用看

这套 JTAG 命令的完整解释在姊妹手册(主线 Linux 手册)第 6 章「JTAG 调试方法论」——那是你亲历过的排雷工具箱,速查形态见附C。

A.3 供电须知:双 type-C 的 ORing 小聪明

UART、JTAG 两个 type-C 口的 5V(VBUS)各经一只二极管汇到主电源——所谓 OR 二极管,就是"谁的电压高用谁",两路互不倒灌。三个推论:

  • 任一口都能独立供电:只插 JTAG 一根线,烧写、ILA 照常工作(实测单 UART 口供电也能跑完整套 Linux);
  • 反过来,"插了线"不证明"插对口"——供电通了只说明 5V 到了,功能口认不认还得看丝印;
  • 入板 5V,再由板上电源电路分轨;PL 相关的 bank 34/35 的 VCCO 是 3.3V(上节知识框),这就是排针全部 LVCMOS33 的由来。
警告:排针上没有 GND 脚

JP1/JP2 各 40 脚里,厂商把 4 个脚给了电源:11/12 脚 = VCC_5V,29/30 脚 = VCC_3V3,其余 36 个全是信号脚——没有一个 GND(已逐脚核对原理图)。含义:

  • 杜邦线数脚时千万别把电源脚当信号脚:5V 直怼某个信号脚可能损坏对方芯片;
  • 接 USB-TTL(ch07 选做)这类需要共地的外设时,GND 得从别处取——用万用表蜂鸣档在板的安装孔/金属外壳触点上找到与电源地相通的点,确认后再接;
  • 原理图上也没找到专门的 GND 测试柱,所以"共地从哪来"必须先量后接,这是飞线纪律。

A.4 时钟树:PL 只有一个 50MHz

PL 侧全板唯一时钟源:一颗 50MHz 有源晶振,经 33Ω 串阻接到引脚 N18(bank 34,时钟专用脚 MRCC)。于是:

  • 每个 Lab 的约束都从这三行开始(取自 lab01.xdc):
create_clock -period 20.000 -name sys_clk [get_ports clk]   # 50MHz = 周期 20ns
set_property PACKAGE_PIN N18 [get_ports clk]
set_property IOSTANDARD LVCMOS33 [get_ports clk]
  • PS 有自己独立的 PS_CLK,DDR 有自己的时钟域——PL 和 PS 是两套时钟,上电时互相不认识,直到 ch09 会师课 PS 才经 GP 口把 FCLK0 送进 PL;
  • 片内还有 4 个 PLLE2(锁相环,Phase-Locked Loop, PLL)可把 50MHz 倍频/分频,课程进阶篇之外自行探索;
  • 引脚的演变(N18 的退役):ch01~ch08 的设计都活在 N18 的 50MHz 域;ch09 起,设计整体搬到 PS 送来的 FCLK0 域(N18 退役)——那时 XDC 里 N18 三行撤下,换成对 FCLK0 网络手写 create_clock(直例化 PS7 没有自动约束,不写的话时序报告"全绿"是假象)。详见 ch09。

A.6 RST 按键警示:一按回到解放前

板上丝印 RST 的按键不是"重启程序",是整芯片硬复位(原理图上它经 100Ω 串阻拉低 SYS_RESET_N,直通 PS 复位树)。按下去的一瞬间,两个世界同时遭殃:

按下 RST — PS 硬复位,PL 配置随之清空
↓
PS 侧 — Debian 立刻重启:ssh 断开、串口滚启动日志,等几十秒才回来
↓
PL 侧 — 你烧的比特流没了:LED 灭、排针无输出,必须重新烧写(program.tcl 或 ch09 的装载命令)
教训(导师实测):消抖课手一滑,一个晚上白排

ch02 消抖实验时手就放在按键区——PL_KEY 和 RST 离得近,手一滑按到 RST:LED「啪」地灭了,第一反应是"代码烧崩了",回头查约束、重跑综合,折腾一大圈。其实是配置被清空了,重烧一次比特流就好。任何 Lab 现象突然消失,第一件事问自己:是不是按错键了?

辨认:丝印 PL_KEY 的那个才是我们的按键(接 P14,代码里的 rst_n/key);RST 通常离它不远、个头相仿——上手前先用眼睛把两个丝印分开,这一眼值一个晚上。

动作PS 侧代价PL 侧代价恢复动作
按 RSTDebian 重启(几十秒,ssh 断)比特流清空,需重烧等系统起来 + program.tcl 重烧
按 PL_KEY无无(就是普通输入脚)—
拔插 type-C 重新供电同 RST(整板掉电)同 RST同 RST

A.7 JTAG 互杀:hw_server 与 OpenOCD 抢 FT232H

板上那颗 FT232H 是独占设备:同一时刻只允许一个 JTAG 服务器驱动它。Vivado 的硬件服务器进程 hw_server(Hardware Manager、ILA、烧写都用它)和 OpenOCD(你在主线 Linux 手册里用它排过雷)是死对头——谁后启动谁连不上,症状是 connect_hw_server 卡住、OpenOCD 报 adapter 打不开,看起来都像"板子坏了"。

互杀口诀:开一个,先杀另一个
pkill -x openocd      # 要开 Vivado Hardware Manager / 烧写 / ILA 之前
pkill -x hw_server    # 要开 OpenOCD 之前

小心 pkill -f 的自匹配陷阱(导师亲踩):-f 匹配的是整条命令行,如果你的脚本名、终端命令、或某个中间进程的参数里恰好含"openocd"字样,它会连你自己一起杀——命令敲下去终端突然没了,就是被自己 pkill 的。所以上面用 -x(精确匹配进程名):慢一点,但只杀目标进程。

课程里这颗雷第一次引爆的预定地点是 ch06(ILA 上场那天):如果你此前挂着 OpenOCD 会话,hw_server 大概率起不来。先背口诀,再看现象。

A.8 板上温度读法:XADC 三行命令

Zynq 芯片自带一片 XADC(片内模数转换器,Xilinx Analog-to-Digital Converter, XADC),接着内部温度传感器和各路电源轨——芯片自带的体检报告,不用任何外部仪表。Linux 内核把它挂成 IIO(工业输入输出子系统,Industrial I/O, IIO)设备,读法三行:

ls /sys/bus/iio/devices/                # 找到 iio:device0(设备名 xadc;若没有,先确认内核带 xilinx-xadc)
cd /sys/bus/iio/devices/iio:device0
cat *_raw *_scale *_offset               # 各通道原始值/刻度/零偏,通道文件名以 ls 实际输出为准

换算公式(对任意通道通用):

实际值 = (raw + offset) × scale / 1000

温度通道代进去,得到的是结温(junction temperature,芯片硅片内部温度)——比手摸外壳更真实也更严格。这台板的实测基准:空闲结温约 55°C,各电源轨电压正常(出厂系统上量的;换到自己的 Debian 后建议重测一次,当作新基准)。以后跑长仿真、ILA、重负载时温度往上走是正常;显著高于基准且持续爬升,才值得停下来查。
