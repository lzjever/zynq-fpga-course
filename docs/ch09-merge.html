会师:Debian 装载你的电路

两条技能树,今天在你手里合流:你自己移植的 Debian,装载、驱动、拨动你自己写的电路。

1 · 钩子:这一天你等了两条技能树

回想你手上的两件东西:一条技能树是去年亲历的主线 Linux 移植——U-Boot、内核、Debian、JTAG 调试,你从零搭起了 ARM 这半边;另一条是这门课——从 led_blink 的 33 行到 AXI 从机,你一块块垒起了 FPGA 这半边。

现在看这行命令:

devmem 0x40000000 32 0x00000001

这一枪打中的寄存器,偏移、宽度、位含义——是你上一章亲手设计的。它经过 GP0 总线、五通道握手、落到你的 CTRL 寄存器,bit0 顺着导线点亮 R14。这是全课程的会师时刻(M4),也是这门课为你这个画像独家定制的一幕:别人教程里的"假设你已经有一个 Linux",在你的板上,是"我亲手装的 Debian"。

2 · 战地日记:那颗 FIQ 螺丝(简版)

主路要过 FIQ 验收门,这个门是怎么来的?你亲历过,这里只留三行年表,详细排查过程见姊妹手册第 6-7 章(主线 Linux 手册):

FIQ 风暴事件簿(2026-11)
  1. 现象:主线内核里通过 FPGA Manager(insmod 装载器)写入比特流,约十几秒后整机冻死——PS 侧被快速中断请求(Fast Interrupt ReQuest, FIQ)风暴打穿。
  2. 追凶:JTAG halt 看 PC 停在中断处理;顺藤摸到 GIC 分发器的安全世界配置(寄存器被锁在 TrustZone 一侧,主线内核碰不到)。
  3. 修复:u-boot 阶段提前改写 GIC 配置的 BOOT.BIN 已打包,哨兵脚本待板子断电重启自动执行验收——修复已就绪,等你上电那一刀。

这门课不重复手册的排查细节;你只需要带着一句话进考场:FIQ 风暴 = PS 侧中断控制器的安全配置问题,与你的 PL 电路无关——所以保底路(Variant B)绕开它依然成立。

3 · PS7 直例化:把隔壁那半边接出来

Zynq 是一块硅、两个世界:处理系统(Processing System, PS,ARM 那半边)和可编程逻辑(Programmable Logic, PL,FPGA 这半边)。课程至今你只活了 PL;PS 早已被你的 FSBL/U-Boot/Debian 武装到牙齿。两个世界之间有几根固定的"脐带":GP0 总线(上一章的 AXI 门)和 FCLK 时钟(PS 送给 PL 的节拍)。

行业常规做法是在 Block Design 里拖一个 PS 模块、勾选项、自动连线。我们走一条对你更诚实的路——直接在 Verilog 里例化 PS7 原语,像例化 tick 分频器一样:

PS7 PS7_i (
    .FCLKCLK0        (fclk0),     // PS 送给 PL 的时钟 0:整个设计的唯一节拍
    .M_AXI_GP0_ACLK  (fclk0),     // GP0 总线时钟同源——同域,无 CDC
    .M_AXI_GP0_AWADDR(gp0_awaddr), .M_AXI_GP0_AWVALID(gp0_awvalid), .M_AXI_GP0_AWREADY(gp0_awready),
    // …… W/B/AR/R 通道同理;AXI3 独有信号(ID/突发类)挂空 = 置之不理(ch08 方案甲)
    // 其余几百个端口(DDR/MIO/中断…)未列出 = 挂空,PS 侧自有人管
);

图 1 · 会师全景:PS 侧三件套(devmem、SLCR、FPGA Manager)各走一根脐带(FCLK0 时钟、GP0 总线、PCAP 装载通道)够到你的电路。

装载这条脐带也交代一下:Debian 侧的 FPGA 管理器(FPGA Manager)框架通过 PCAP——处理器配置访问端口(Processor Configuration Access Port, PCAP)——把比特流从内存灌进 PL。你移植时在设备树(Device Tree)里给 fpga 区域留的那几行,今天终于接上实物流。而 ch04 讲过的 .bit/.bin 之别(字节序交换)在这一步兑现:bit2bin.py 的产物才进得了 PCAP。

4 · FCLK0 域方案甲:N18 退役,谁给电路接电源

本设计有一个重大的人事变动:N18(板上 50MHz 晶振)退役了。从 lab01 到 lab07,它一直是你的心跳;现在整个设计改活在 FCLK0 域——时钟由 PS 供给。为什么?

不换域的那颗雷(ch03 回马枪)

假设设计继续跑 N18,而你的 CTRL/SPEED 寄存器活在 FCLK0 域(总线时钟只能用 FCLK,这是 PS7 的硬规矩)。ARM 写一个 32 位的 SPEED,这 32 位跨进 N18 域——多比特跨时钟域,数值撕裂:N18 采样瞬间恰好撞上多位翻转,SPEED 可能既不是旧值也不是新值(ch03 里你亲眼让计数器撕出过 7→15)。呼吸速度偶尔抽风、复现无门——这种 bug 是作品里的定时炸弹。

方案甲一刀斩:全体逻辑搬进 FCLK0 域,一个时钟,雷不存在。代价只有一条:FCLK0 的开关在 PS 手里——所以"使能 FCLK0"那条 devmem 命令,是这门课真正意义上的"Linux 的一条命令,给你的电路接上电源":时钟不来,设计全体冻结;命令一到,呼吸开始。

选做 · 方案乙(想练 CDC 技艺再看)

保持双域也能活:对 SPEED 逐位打两拍 + 握手脉冲(Gray 码只适合计数器,不适合任意值)。ch03 的知识在毕业章回收,教学上很美——但给顶点周加活,本课降为选做,默认方案甲。

顺带一提,这是全书 parameter 主题的第三级跳:ch01 缩仿真时间、ch07 放大波特率(肉眼 UART)、ch09 换主频——pwm_breather 的时间公式按 FCLK0 重新算一遍(README 命令卡里已给结论)。注意 FCLK0 频率不是天上掉下来的:它由 PS 侧 SLCR(System Level Control Register,系统级控制寄存器)的 0xF8000170 号寄存器决定,除数装多少、频率就是多少——先读回,再决定写不写。

5 · 手写 create_clock:时序报告对你的第一句谎话

ch04 你学会读 WNS;ch08 结尾留了个伏笔"什么时候才有 WNS"。现在摊牌:

本课最大的暗坑:全绿是假象

以前用 Block Design 时,Vivado 会替你在 FCLK 网络上自动生成时钟约束。直例化 PS7 没有这层服务——如果你忘了写,FCLK0 网络上没有任何 create_clock,静态时序分析器不知道该按什么周期检查你的电路,于是它干脆什么都不查,报告里 WNS 一片"绿"。看起来时序全过,其实是根本没分析。这种"成功的假象"比红色报错危险十倍。

解药一行,写进 lab09.xdc:

create_clock -period 20.000 -name fclk0 [get_pins PS7_i/FCLKCLK0]

(20ns = 50MHz,与 SLCR 里配的频率一致;哪天改了 FCLK0 频率,这行必须同步改,否则 WNS 又是错账。)

6 · 动手:L0 点灯(两条路,你走一条)

先 build 出比特流(vivado -mode batch -source build.tcl,确认 WNS ≥ 0 且不是灰的)。然后按验收门状态选路:

主路 A · FPGA Manager(FIQ 门内)Variant B · JTAG + devmem(保底)
谁装载Debian:./load_fpga.sh(bit2bin → scp → echo 固件名)PC:vivado -mode batch -source program.tcl
前置blink.bin 三绿验收已过无;但开 Vivado 前先 pkill -f openocd(JTAG 互杀,附录 A)
装载后已在运行态设计还冻着——FCLK0 没使能

两条路互斥,谁后到谁生效(后装的流顶掉先装的)。Variant B 装完的第一件事,就是"接电源"仪式:

# Debian 上(ssh root@192.168.1.10):先读后写
devmem 0xF8000170                     # 看 FCLK0 控制寄存器现状(bit24=1 已是活的)
devmem 0xF8000170 32 0x01011400      # 使能,IO PLL 1000MHz ÷20 ÷1 = 50MHz

# L0 点灯 / 灭灯
devmem 0x40000000 32 0x00000001
devmem 0x40000000 32 0x00000000
地址是怎么算出来的(你的本能问题)

0x4000_0000 = GP0 的基址 + 偏移 0x00(CTRL)。单从机直挂 GP0 没有互连重映射:Verilog 里接的哪根地址线,ARM 就直达哪个偏移。0x4000_0000+0x04 = SPEED。软件里的"地址映射"四个字,在硬件侧就是一根译码线——两个世界在这里词汇表合并。

7 · 动手:L1 接上呼吸,改速度

L0 的 LED 是"电灯开关";L1 把 ch05 的呼吸灯接进挡位:SPEED 非 0 即呼吸挡,数值越大越慢:

devmem 0x40000004 32 0x0000017E   # ≈ 1 秒一次呼吸
devmem 0x40000004 32 0x000005FB   # ≈ 4 秒一次呼吸
devmem 0x40000004                  # 读回:应回显 0x5FB(读 = 回值)

公式(数字自己验一遍,别信我——ch00 的教训):呼吸周期 = (SPEED+1) × 510 × 256 ÷ FCLK0 ≈ (SPEED+1) × 2.61ms @50MHz(510 = 三角波 255 步上 + 255 步下)。你现在做的事,和游戏引擎里调粒子参数、和 systemd 里改服务阈值,在工程形态上完全同构:寄存器 = 服务的配置项。你只是第一次站在了配置项的另一端。

8 · 毕业考:一条 devmem 写的全路径

不看任何资料,白纸手绘:devmem 0x40000000 32 1 从敲下回车到 LED 亮起,依次经过哪些站?这是全课程知识的一条线串——参考答案(先画完再看):

① shell 解析 devmem — busybox 工具,目标物理地址 0x40000000、宽 32、值 1
↓
② /dev/mem 映射 — 用户态不能直接摸物理地址,devmem 借内核开的窗口进去
↓
③ ARM 执行 store 指令 — 地址落入 0x4000_0000 起的 GP0 窗口,PS 内部互连把它路由向 PL
↓
④ GP0 发起 AXI 写 — AW/W 通道握手 → 你的从机 write_fire → B 回执(ch08 的三拍)
↓
⑤ CTRL 寄存器落值 1 — bit0 = 1;SPEED=0,挡位 mux 选手动挡
↓
⑥ led 输出 1 — 经过输出缓冲、R14 引脚、限流电阻,LED 亮

画对了,你就同时回答了"软件怎么摸硬件"和"这大半年你学的是什么"两道题。

9 · 常见坑

坑 1 · JTAG 互杀(hw_server vs OpenOCD)

你跑过 OpenOCD,它和 Vivado 的 hw_server 抢同一个 FT232H。开 Vivado 烧写/ILA 前 pkill -f openocd;反过来用 OpenOCD 前杀 hw_server。互杀口诀在附录 A/C。

坑 2 · 两种装载互斥,谁后到谁生效

JTAG 烧完再 echo 固件名,流被顶掉;反过来亦然。现象是"刚才明明亮着怎么灭了"——先想装载顺序,再想代码 bug。

坑 3 · .bit 直接 echo 给 FPGA Manager

必须先 bit2bin.py(字节序交换,ch04 讲过同步字)。症状:装载"成功"、state 却不是 operating,或 PL 行为全乱。

坑 4 · 时序报告全灰还当全绿

看到"no timing constraints"字样 = create_clock 没生效,回第 5 节。灰的 WNS 不是 0,是"没考过试"。

坑 5 · RST 键

老规矩:丝印 RST = 整芯片硬复位,清 PL 配置 + 重启 Debian——会师成果一键清零。按键只认 PL_KEY(P14)。

坑 6 · AXI3 直挂不工作(待实测门)

ch08 的两案在此兑现:写 LED 无反应/读回脏值 → 切 build.tcl 里的预案乙(垫 AXI Interconnect,全脚本化不进 BD)。这是全书三项"待实测"里你今天实地验证的那一项。

11 · 三档自测

A(送分题,你的主场)· 为什么用户态不能直接写 0x40000000,而 devmem 可以?

B(预测题)· 把 lab09.xdc 的周期从 20ns 改成 10ns(SLCR 不动,FCLK0 仍是 50MHz),综合实现后 WNS 会怎样变化?设计在板上会变快吗?

C(排错题)· 同学说"我 LED 不亮,但 devmem 读回 0x40000000 能正确回显写进去的值"。从机活着、灯却不动——列出你怀疑的三个站点。

展开答案(先自己答,再对)

A:用户态进程摸不到物理地址;devmem 通过 /dev/mem(内核开的物理内存窗口)替你读写。这也是 mmap 一类工具的共同原理——你移植期早就会,此题是给信心。

B:约束改严一倍,Vivado 按 100MHz 检查同一条电路,WNS 大约减半(可能仍为正,因为这个设计很轻)。但板上什么都不会变——约束只影响工具的分析口径,不改电路;真实节拍由 FCLK0 决定。约束写错 ≠ 电路跑错,但要记住:约束是你对工具的承诺,承诺错账就全错。

C:① SPEED 寄存器非 0——挡位 mux 在呼吸挡,CTRL bit0 不通到 LED(写 0x40000004 清零即验);② LED 写的是 0x40000000 吗——写串到未映射偏移(本从机未映射也回 OKAY,见 lab09 思考题);③ R14 引脚/LED 硬件本身(JTAG 烧个 lab01 blink.bin 隔离验证)。读回正确证明的总线与寄存器半区是好的,排查应向"寄存器之后"走。
