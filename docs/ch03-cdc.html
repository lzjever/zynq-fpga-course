CHAPTER 03

亚稳态:时间的灾难

触发器也有"来不及看清楚"的瞬间——给 ch02 的悬案翻案,顺便立下 FPGA 设计第一条军规。

1 · 钩子:ch02 的卷宗里,还有个从犯在逃

上一章裸版对比实验的结论是:按一下 LED 乱翻,主犯是机械抖动,你的消抖器已经把它拿下归案。但当时我们还留了一笔账:

知识 · ch02 留下的那笔账

裸版乱翻其实有两个因子:抖动是主犯(人眼可见、每按必演),但还有个阴险的从犯——你把 P14 这根和 50MHz 时钟毫无关系的信号直接接进了触发器。它 99.9% 的时候乖得像只猫,剩下那 0.1% 的作案,消抖器拦不住,仿真器也看不见。这一章,就是来结这个案的。

你大概一次都没遇过它——概率上你大概率遇不上。但"我按了 50 次没出事"和"它不会出事"是两句话。这章要干的四件事:

  1. 搞懂它是什么(亚稳态)、为什么会发生(采样窗口);
  2. 在仿真里亲眼看见它的"多比特兄弟"——数值撕裂(确定性复现,不靠运气);
  3. 承认仿真器的盲区:亚稳态本身,仿真器演不了;
  4. 所以按行业军规办事:打两拍,回炉你的 lab02 成 v2,上板验收。

2 · 这一章要学会什么

  • 能用自己的话说出:异步信号为什么可能让触发器采样失败,失败时输出是什么样子;
  • 能给出建立时间/保持时间的人话定义,并指出采样窗口在哪里;
  • 能解释"撕裂":多比特信号跨域时,为什么每个位单独看都合法,合起来却是错数;
  • 能说出打两拍同步器的原理、两个局限(只压概率不压延迟;一次只救 1 位);
  • 能把 lab02 回炉成 v2(同步 → 边沿 → 消抖),板上按 50 次零误翻,仿真压测 10 万次零误脉冲;
  • 能对 MTBF 做一次数量级粗算,体会"每加一拍,指数翻倍"。

3 · 原理一:你的按键和你的时钟,素不相识

先定义两个词。异步信号(Asynchronous Signal):和你设计的时钟没有任何时间关系的输入信号——P14 上的按键就是,它的按下时刻由你的手指决定,和 50MHz 晶振的节拍毫无约定。相对地,我们把"听同一个时钟号令的所有触发器"称为一个时钟域(Clock Domain)。信号从一个时钟域进入另一个时钟域,就叫跨时钟域(Cross-Domain Crossing, CDC)。

你的按键信号要进入 50MHz 时钟域,唯一的入口是触发器:每个时钟上升沿,"咔嚓"拍一张照片。问题就出在这张照片上——触发器拍照不是零成本的,它对被拍对象有一个要求:

在时钟沿的前后一小段时间里,输入必须保持稳定。

4 · 原理二:采样窗口——建立时间与保持时间

触发器内部是若干个门在"接力"。要稳定地存住一个值,输入得在时钟沿之前一小段时间就到位(给接力留出提前量),并且在时钟沿之后再稳住一小会儿(最后一个门还没松手)。这两段要求就是:

  • 建立时间(Setup Time, tsu):时钟沿前,输入必须已经稳定的最短时间;
  • 保持时间(Hold Time, th):时钟沿后,输入必须继续稳定的最短时间。

两段时间拼成的窗口,就是触发器的采样窗口——期间输入变了,就是违反时序(violation)。

图 1 · D 在采样窗口(橙色=建立、蓝色=保持)内翻转 → 违反时序 → Q 拍出一张"糊"的照片

同步设计里,这个要求由工具自动满足(下一章的 WNS 就是工具给你的检查回执)。但异步信号不一样——它变化的时间是随机的,总有一些变化恰好落进采样窗口。撞上了会怎样?这就是本章的主角登场。

5 · 原理三:亚稳态——悬在中间的电压

亚稳态(Metastability):触发器在采样窗口内遇到输入翻转时,输出不再干净地是 0 或 1,而是悬在高低电平之间的某个中间电压上,像铅笔尖朝下立在桌面上——立是立住了,但一阵风(电路噪声)就能吹倒,倒向哪边由噪声决定,与输入原本想表达的值无关。

图 2 · 亚稳态的收敛像掷硬币:倒向哪边、多久倒,都不知道。B 还算幸运,C 才是事故现场

两个关键认识,决定后面所有对策:

  • 亚稳态无法消除。它是物理,不是 bug。异步信号和时钟的对齐是随机的,采样窗口永远存在,总会有撞上的那一次。能做的只有把后果的概率压到可忽略。
  • 它传染。悬在中间的电压如果直接喂给下一级逻辑,下一级可能把它读成 0、读成 1、或者自己也悬住——同一个糊值,不同下游读出不同结果,这是比"读错一位"更诡异的事故来源。

先看它的"多比特兄弟":撕裂

单比特亚稳态是概率事件,演示要靠运气。但多比特信号跨时钟域有一个确定性的亲戚,可以先看:一个 4 位二进制计数器从 7(0111)变到 8(1000)时,四位同时翻转。真实芯片里,这四根线从计数器走到采样触发器,路径长短不一(术语叫偏斜(Skew),布线造成的不齐),到达自然有先有后。如果采样沿恰好落在这段"新旧混杂"的窗口里,拍到的就是半个旧值拼半个新值——数值撕裂(value tearing):

图 3 · 撕裂的诞生:采样沿落在"高位已到、低位未走"的窗口 → 拍到 1111 = 15

撕裂比单比特亚稳态"亲民"得多:它是确定性的(窗口就在那里,采样沿扫过去总会撞上),所以在仿真里就能复现——这正是下面动手环节的主菜。记住这个画面,7→8 的路上会路过 15,回头 15→0 的路上还会路过 7(仿真实测,两发都能抓到)。

6 · 动手一:撕裂仿真(40 分钟,本 Lab 主菜)

位置:labs/lab03-cdc/。先交代一个坑,这也是本实验的灵魂:

警告 · 理想 RTL 仿真里,计数器"永远不会"撕裂

Verilog 的非阻塞赋值让计数器各位在同一时间片内原子更新。目的时钟的采样沿无论落在哪,读到的要么全旧、要么全新——拍频扫的是采样相位,扫不出"半新半旧"。真实世界的撕裂来自各位布线延迟不等,而理想仿真模型里根本没有布线。所以本实验必须由 TB 显式注入各位延迟(给每一位接一根不等长的"导线"),把布线偏斜模拟出来。这不叫作弊——这正是"知道仿真器缺什么,就补什么"的工程能力。

tear_demo.v:一对双胞胎计数器

// labs/lab03-cdc/tear_demo.v(节选;完整文件带逐行注释)
module tear_demo (
    input  wire       clk_src,   // 源时钟域:两个计数器活在这里
    output reg  [3:0] bin_q,     // 二进制计数输出(未防护,等着被撕)
    output reg  [3:0] gray_q     // 格雷码计数输出(对照品)
);
    // 格雷码(Gray Code)变换:右移 1 位再异或自己。
    // 性质:相邻数值只差 1 位——这是它的全部魔法。
    wire [3:0] bin_gray = (bin_q >> 1) ^ bin_q;

    reg pace = 1'b0;                      // 每 2 拍才 +1(让相邻变化隔 40ns,
    always @(posedge clk_src) pace <= ~pace; //  撕裂窗口不重叠,判据才干净)

    always @(posedge clk_src)
        if (pace) begin
            bin_q  <= bin_q + 1'd1;         // 0,1,2,...,15,0,...
            gray_q <= bin_gray;             // 跟着走,每步恰好翻 1 位
        end
endmodule

格雷码(Gray Code)是二进制的亲戚:相邻两个数值的编码恰好只差一位(0→1→2→3 的格雷码是 0000→0001→0011→0010)。计数器每步只动一位,跨域的每一根线上"新旧混杂"不再可能拼出怪值——采样要么旧值要么新值,都是合法计数。

tear_tb.v:延迟注入 + 三路对照

// 两个"互不相认"的时钟:同样标称 50MHz,周期差 0.3ns。
// 采样沿会在源周期里缓缓扫动(每拍移 0.3ns),总会撞进撕裂窗口。
always #10.00 clk_src = ~clk_src;    // 周期 20.00ns
always #9.85  clk_dst = ~clk_dst;    // 周期 19.70ns

// ---------- 灵魂:给每一位接一根"不等长的导线" ----------
// 延迟故意反着排:最高位最短、最低位最长——于是 7→8 的路上,
// 采样沿会先看到高位已变、低位未变 → 抓到 1111 = 15。
assign #4 bin_skew[0] = bin_q[0];    // 最低位:绕最远的导线
assign #3 bin_skew[1] = bin_q[1];
assign #2 bin_skew[2] = bin_q[2];
assign #1 bin_skew[3] = bin_q[3];    // 最高位:抄近道

assign #4 gray_skew[0] = gray_q[0];  // 格雷码吃完全相同的延迟
// ...(#3/#2/#1 同上)

wire [3:0] bin_clean = bin_q;        // 零延迟对照:理想 RTL 的样子

三路信号被同一个 clk_dst 域的触发器采样,检测器盯着每个新样本:计数器 40ns 才 +1,而相邻采样各自的"视野"(含偏斜)只有 22.7ns 宽,装不下两次 +1——所以合法样本 = 上一拍值,或上一拍值+1,其他任何值都是撕裂。跑起来(XSIM 三步舞,命令卡在 README):

7 · 动手二:仿真器的盲区——X 演不出收敛

有人会想:那我给同步器第一拍强行注入一个 X(未知态),看看它两拍后收敛到 0 还是 1?想法很好,TB 里也真能这么干(force,下一行代码)。tear_tb 的阶段二就演了这一出:强制第一拍输出为 X,然后等两拍——

 盲区演示: force q1 = X 两拍后, q2 = x
 (物理世界会收敛到 0/1;四态仿真永远 X —— 安全性仿真不出来)

X 进,X 出。四态仿真(Verilog 的 0/1/X/Z 四个值)里的 X 是"逻辑上的未知",它没有物理、没有电压、不会自己倒向 0 或 1——只会原样传染给下一个触发器。物理世界的亚稳态是"悬在中间的电压",噪声会推它收敛;仿真里的 X 是个标签,谁也不推它。把上面两件事合起来:

警告 · 仿真器的盲区(两条)

① 零延迟理想仿真里多比特跨域看不到撕裂(必须手工注入偏斜);② 强制 X 演不出亚稳态收敛(X 只传染不收敛)。结论:"同步器安全"这件事,仿真证明不了。仿真能证功能对错,证不了概率安全。所以工程上不靠实验证明安全,而是直接上保险——这就是打两拍的地位:不是"实验验证有效的方案",是"因为无法验证,所以必须上保险"。

另外记一条规矩:force/release 是 TB 专用方言,出现在设计代码里综合器直接报错(ch01 讲过的"不可综合方言",这里又添一员)。

8 · 打两拍:给亚稳态一个"安静的房间"

既然亚稳态的收敛需要时间(物理上几纳秒内基本都会倒向一边),对策就朴素得惊人:给它一个完整的时钟周期去收敛,别打扰:

图 4 · 两级同步器(Two-stage Synchronizer),"打两拍":两个触发器背靠背接同一时钟
// v2 补丁:两行,装进你 lab02 的最前面
reg  [1:0] sync_ff;
always @(posedge clk) sync_ff <= {sync_ff[0], key_raw};  // 两级同步器
wire key_sync = sync_ff[1];
// 原 lab02 里 key_raw 的全部下游(边沿检测、消抖计数)改吃 key_sync

两个局限必须说清,它们是无数事故的源头:

  • 只压概率,不压延迟。打两拍后 key_sync 比 key_raw 晚 2 个时钟周期,而且亚稳态收敛倒向哪边依然是随机的(可能 0 可能 1)。它保证的是"下游看到的值永远干净",不是"值永远对、永远准时"。
  • 一次只救 1 位。同步器救的是单根信号线。多比特总线各自打两拍?每位都干净了,但图 3 的撕裂在所难免——各位的亚稳"倒向"互相独立,拼起来还是怪值。多比特跨域要靠格雷码(计数器类)或握手(数据类),本书只走到格雷码这一步,握手在毕业路线图里等你。

9 · MTBF:这张保险单值多少钱

平均无故障时间(Mean Time Between Failures, MTBF):两次亚稳态事故之间的平均间隔。教材公式长这样(选学,看懂结构就行):

MTBF = e^(t_r / τ) / (W × f_clk × f_data)

t_r    :留给亚稳态收敛的时间(打两拍 ≈ 一个完整时钟周期,20ns)
τ      :器件的"收敛时间常数"(工艺决定,几十皮秒量级)
W      :采样窗口宽度(建立+保持,几十皮秒量级)
f_clk  :采样时钟频率(50MHz)
f_data :异步信号变化频率(按键约 10Hz;若是跨域计数器就大得多)

不用记公式,感受一个数就够:分子上那个指数。用 τ≈20ps 粗算,一个完整周期 20ns 的收敛时间是 1000 个 τ,于是 e^1000 ≈ 10^434——分母上无论是什么频率量级,都被这个指数拍在地板上。每多给一拍,指数翻倍:一拍 10^434,两拍 10^868。这就是"打两拍"的全部原理:不是把概率调成零,而是把它压到"宇宙年龄都不够等一次事故"。

知识 · 既然一拍就"够安全",为什么打两拍?

看数字确实一拍就天文数字了——但 τ 和 W 是典型值,厂商不给保证;你的第一拍后面真有几个完整周期、挂了什么逻辑,设计大了谁也说不准。工程师的态度是:两拍几乎免费(2 个触发器,占 7z020 的十万分之二),买的是"不依赖任何数字"的确定性。保险单便宜,就别省。真正天天出事故的其实不是单比特亚稳态,而是撕裂和"同步器中间插了组合逻辑"这类结构性错误——下面坑表见。

压测不缩参数10 万次 × 20ms = 2000 秒仿真时间,一晚上跑不完阈值和激励节奏同比缩小 25000 倍

12 · 小结与自测

一条线串起本章:异步信号撞采样窗口 → 亚稳态(悬而不决,无法消除,仿真不出)→ 所以买保险:单比特打两拍,多比特格雷码;保险的底气来自 MTBF 的指数。你的 lab02 现在是 v2:同步 → 边沿 → 消抖,多花了 2 个触发器,买下"入口永远干净"。

本章新词卡(附录 B 汇总)

异步信号(Asynchronous Signal)· 时钟域(Clock Domain)· 跨时钟域(Cross-Domain Crossing, CDC)· 建立时间(Setup Time, tsu)· 保持时间(Hold Time, th)· 亚稳态(Metastability)· 偏斜(Skew)· 数值撕裂(value tearing)· 两级同步器(Two-stage Synchronizer,打两拍)· 格雷码(Gray Code)· 平均无故障时间(Mean Time Between Failures, MTBF)

自测(先答再看,三档)

A · 概念复述:用一句人话说清——为什么打两拍不能用在 8 位总线上,而格雷码计数器可以裸采样?

B · 预测(先猜后验):把 TB 里四根延迟线改成全部 #2(等长),重跑,撕裂次数会变成多少?为什么?——改一下,跑一遍,对答案(应当是 0:撕裂的根因是"不齐",不是"延迟"本身)。

B2 · 预测:两拍加到三拍,MTBF 往哪个方向变?代价是什么?(方向:指数再翻倍,天文数字×天文数字;代价:多 1 拍延迟、多 1 个 FF——通常不划算,所以军规是"两拍")

C · 排错:v2 里有人图省事,消抖计数的清零条件仍然接的 key_raw(未同步),边沿检测吃的却是 key_sync——两路信号时间上错开了 2 拍。这会出什么事?

答案(点开前先自己写一遍)

A:总线各位的"糊值收敛方向"互相独立,拼起来可能半新半旧(撕裂);格雷码每步只动 1 位,任一时刻最多一根线处于"新旧之间",采样到的永远是某个合法值。
B:等长延迟 = 同时到达 = 和零延迟同理(只是晚 2ns),原子更新照旧,撕裂 0 次。
B2:见上;军规两拍是"够狠且免费"的平衡点。
C:消抖计数器被未同步的野信号清零——清零动作本身可能落在亚稳窗口,产生一次"半清零"的糊值;而且两路时间错位,可能出现"计数刚被判稳定,野信号又把它清掉"的竞争,偶尔漏脉冲或出双脉冲。一句话:一个模块的所有输入必须活在同一个(干净的)世界里。
