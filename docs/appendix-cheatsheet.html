用卡原则

每条命令都在正文里教过一遍(表内"学在"列标了出处),这里只给命令 + 一行注释,不重复原理。工具版本口径:Vivado 2026.1 免费档(安装界面名 Vivado ML Standard,授权页称 Basic);OpenOCD 配置沿用姊妹手册仓库的 openocd-z7nano.cfg。"主机"= 你的电脑,"板上"= 板子的 Debian 里。

C.1 Tcl 五步舞:从源码到比特流(学在 ch04)

create_project lab01 ./lab01 -part xc7z020clg400-2 -force   # ① 建工程(芯片型号别抄错,-2 是速度等级)
add_files led_blink.v                                       # ② 加源码
add_files -fileset constrs_1 lab01.xdc                    # ② 加约束(引脚/时钟)
set_property top led_blink [current_fileset]              # ② 指定顶层模块
launch_runs synth_1 -jobs 8                              # ③ 综合:Verilog → 门级电路
wait_on_run synth_1                                        # ③ 等它跑完
launch_runs impl_1 -jobs 8                               # ④ 实现:内部分三幕(映射/布局/布线),住进真实 LUT/FF
wait_on_run impl_1                                         # ④ 等它跑完
launch_runs impl_1 -to_step write_bitstream -jobs 8       # ⑤ 生成比特流 .bit
wait_on_run impl_1                                         # ⑤ 等它跑完
在哪命令用途
主机vivado -mode batch -source build.tcl一条命令跑完五步(~2 分钟吐出 WNS 和 .bit),不用开 GUI
脚本尾set wns [get_property SLACK [get_timing_paths]]读时序最差负余量(Worst Negative Slack, WNS)——≥0 才算时序达标
脚本尾report_utilization资源账本:查找表(Look-Up Table, LUT)与触发器(Flip-Flop, FF)用量,记进每课 README

C.4 Linux 侧:ssh / 串口 / FPGA Manager / devmem(学在 ch09)

在哪命令用途
主机python3 uart.py listen 120串口监听 120 秒(抓启动日志;上电前先开,工具支持自动重连)
主机python3 uart.py probe发个回车,探板子当前停在哪个界面
主机python3 uart.py send "文字"发一行看回显(登录名、命令都靠它)
主机ssh root@192.168.1.10上板(密码 root);比串口快,日常操作走这条
主机python3 bit2bin.py lab01.bit.bit → .bin:剥头 + 每 32 位字节序交换(FPGA Manager 的要求;脚本在 labs/)
主机scp lab01.bin root@192.168.1.10:/lib/firmware/把 bin 送进板上固件目录
板上echo lab01.bin > /sys/class/fpga_manager/fpga0/firmware让 FPGA Manager(Linux 内核的 FPGA 装载框架)装载你的电路——ch09 会师主路
板上cat /sys/class/fpga_manager/fpga0/state查状态:operating = 装好,PL 已在跑
板上devmem 0xF8000170 32 值写 SLCR(系统级控制寄存器,System-Level Control Registers, SLCR)使能 FCLK0——值的除数计算见 ch09"会师仪式"
板上devmem 0x40000000 32 0x2往 GP0 直挂从机的 0 号寄存器写值(示例:写 duty=2;地址怎么来的见 ch09)
板上devmem 0x40000000读回:验证版本魔数 / 寄存器写对了没

C.5 OpenOCD 三板斧:halt / reg pc / resume(学在姊妹手册第 6 章)

在哪命令用途
主机lsusb | grep 0403:6014先确认 FT232H 在 USB 上(物理层不通,后面全白搭)
主机pkill -x hw_server开 OpenOCD 前必做:清掉 Vivado 的 JTAG 服务器(互杀口诀,附A.7)
主机openocd -f openocd-z7nano.cfg -c "init" -c "targets" -c "shutdown"验链路:应列出 zynq.cpu0 / zynq.cpu1 两个目标
主机openocd -f openocd-z7nano.cfg -c "init" -c "targets zynq.cpu0" -c "halt" -c "reg pc" -c "resume" -c "shutdown"三板斧:暂停 → 问"你在哪"(读 PC)→ 放行;隔几秒再来一次,两次 PC 一样=卡死,不一样=还在跑
主机openocd -f openocd-z7nano.cfg -c "init" -c "halt" -c "mdw 0xF800025C" -c "resume" -c "shutdown"读 BOOT_MODE 寄存器:读回 5 = 跳线在 SD 档(附A.2)

C.6 急救区:看门狗口诀

口诀:出问题,先问两句——"能不能重启?重启的代价是什么?"

任何卡死、任何玄学,先把问题分成"重启能救的"和"重启要付代价的",再动手。代价从小到大:重烧 PL(半分钟,program.tcl)< 重新装载(一条 echo)< 整板重启(Debian 起来要几十秒,且 PL 配置必丢——启动链里没有比特流,重启后要重新烧/装载)。板上 reboot、按 RST、断电,都属于最后一档。

症状第一反应为什么 / 详见
板上现象突然消失(LED 灭、排针无输出)是不是按错键了?RST = 整芯复位RST 一按:Debian 重启 + PL 配置清空,两样都要恢复;附A.6
connect_hw_server 卡住 / OpenOCD 报 adapter 打不开pkill -x 杀掉对方FT232H 独占,两个 JTAG 服务器互杀;附A.7
串口完全静默(连乱码都没有)查跳线是否 SD 档;再 mdw 0xF800025C(5 才对)不在 SD 档时 BootROM 空等,全静默最像"板子坏了";附A.2
电脑显示"已连接",板子 ping 不通网线换到 PS ETH 口单边有链路 = 插到 PL ETH 了(它没驱动);附A.2
装载比特流后 ssh 卡死、板子冻住别慌着重启,先翻 ch09 战地日记FIQ 风暴的当前状态与验收门写在 ch09(GIC 修复待断电验证);ch09
JTAG 烧完,发现之前 FPGA Manager 装的电路没了(或反过来)正常,重装一遍要的那个两路装载互斥,"谁后到谁生效";ch09
综合/实现报时序错误,WNS 是负数先查 XDC:create_clock 在不在、周期 20ns 对不对没约束时钟时时序报告没有意义(全绿也是假象);ch04
