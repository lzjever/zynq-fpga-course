## 0. 设计立场

**认知主线(全书一句话):学会用电路的方式处理时间。**

- blink = 数时间;消抖 = 量时间(20ms);亚稳态 = 时间对不齐的灾难;PWM = 时间的平均;ILA = 冻结时间观察;UART = 用时间编码信息;AXI = 两个世界按节拍握手;会师 = Debian 的时间与硅片的时间合流。
- 每章只引入 **1-2 个新概念**(逐章见表),其余全是旧概念的复用与组合。
- 工具永远在"内容需要它的那一刻"登场(§2.4 穿插表),不设独立"Vivado 进阶技巧"章。

**页数盘点(合规 10-14)**:首页目录(壳已有)+ 第 0-9 课(10 章,ch00 已存在)+ 附录 A 板卡手册 + 附录 B 术语表 = **13 页,其中新写 12 页**。

### 1.2 四个成就时刻(里程碑)

- **M1 · 第一次看见时间(ch01)**:在仿真波形里亲眼验证 2.98Hz 公式、解开 ch00 实验 2 留下的"半亮"悬案——"半亮是这世界对你撒的第一个谎,波形不会撒谎"。
- **M2 · 第一件自产电路(ch02)**:从零设计(不是改)消抖器,自己写 TB 验证,交作业——身份从"改代码的人"变成"设计电路的人"。
- **M3 · 让硅片呼吸 + 看见芯片内部(ch05-06)**:呼吸灯渐亮渐灭,ILA 在线看到自己芯片里 duty 沿正弦表爬升——情绪价值最高点,安排在课程中后段续航。
- **M4 · 会师(ch09)**:自己移植的 Debian 用 FPGA Manager 装载(或 JTAG 引导)自己写的 RTL,`devmem` 写自己设计的寄存器改变呼吸灯速率——两条技能树在学员手里合流。此高光为这位学员独家定制。

## 2. 全局机制设计

### 2.1 页面统一模板(在 BRIEF 六段式上前后各加一段)

开场**钩子**(一个反直觉现象/悬案/他熟悉事物的另一面)→ 目标 → 原理(带图)→ 动手 → 现象与验证 → 常见坑 → 小结 + 自测题 → **下一课预告**(结尾埋钩,衔接下一章开场,§4 全链表)。

### 2.2 练习与比例

- 正文篇幅:原理 ≈ 35%,动手 ≈ 65%;动手内部:仿真 ≈ 60%、上板 ≈ 40%(ch01-03 偏仿真,ch05 后偏上板;ch08 纯仿真、ch09 纯 Linux 侧)。
- **自测题固定三档**(每课 3-5 题,全部可自判,不出名词解释填空):
  - A 概念复述:用"人话一句话"说清 X,禁止背定义;
  - B 预测题:改一处代码,**先猜后验**(沿用 ch00"改三个数字"实验的成功模式,此为全书签名题型);
  - C 排错题:给一段带 bug 的代码,题目素材取自本章"常见坑"。
  - (可选 D 埋雷题:最后一题指向下一课,不计分。)
- 每章自测样例见 §3 各章条目。

### 2.3 Lab02"先自己写再看参考"机制(ch02 落地设计)

1. 课程页**不含参考实现正文**。结构:需求书回顾 → 空白框图(填空题形式)→ 三关验收清单 → 提示阶梯(hint 三级,`<details>` 折叠,静态零依赖)→ 参考实现(最后一级折叠)→ 差异笔记模板。
2. **三关检查点**(全部在仿真里判定,现象客观):
   - 关 1:消抖后电平干净(TB 注入带抖动的按下序列,输出电平无毛刺);
   - 关 2:按一次恰好输出 1 个 clk 宽的单周期脉冲(用脉宽计数器在 TB 里自动断言);
   - 关 3:抖动参数化(5ms/10ms/20ms 三档)重跑,三关全过——证明设计吃的是"参数"不是"巧合"。
3. **提示阶梯**:hint1 = 框图答案(只有方框和箭头);hint2 = 关键 always 骨架挖空(判断结构在,表达式空着);hint3 = 完整参考实现。规则:**卡壳超过 45 分钟才准展开下一级**(保心流挑战区:防呆坐,也防秒看)。
4. **交作业定义**:三关波形截图 + 3 行差异笔记("我的写法 vs 参考:哪里等价 / 哪里我更清晰 / 哪里我没想到")。看完参考必须写,防止"抄完即忘"。

### 第 1 课 · 仿真入门:把时间拉到眼前(约 3h;配套 Lab01-sim)

- **钩子(开场)**:"ch00 实验 2 说 cnt[0] 让 LED '半亮'——半亮是谎言,是你的眼睛在偷懒。真相在波形里,而我们没有示波器,但有一台免费的时间显微镜。"(悬案钩子 + 工具缺口钩子:Lab02 需求书里那个"testbench 骨架"到底是什么)
- **学习目标(可检验)**:
  1. 能说出测试台与被测电路的本质区别(一个被综合成电路,一个是"写给仿真器的软件"),并举出 2 个只在 TB 里合法的语法(`#` 延时、`initial`);
  2. 能为 led_blink 写出最小 TB(时钟产生、复位释放、跑 N 周期),跑通 XSIM,用游标测出 cnt[23] 方波周期,与公式 50M/2^24 误差 < 1%;
  3. 能用 parameter 参数化计数位宽,解释全尺寸仿真为何要 1600 万周期、改小后 1 分钟内跑完;
  4. 能在波形里"读出"半亮真相(25MHz 翻转)并写 3 句话解释;
  5. 能复述免费档仿真限额(设计实例数)并说出本设计距离限额的数量级差距。
- **核心内容点**:TB 三要素(时钟/激励/观察);`initial`、`#`、`$display`、`$finish`;仿真时间 vs 物理时间;`timescale` 一句话版;parameter 与实例参数覆盖;可综合子集 vs 验证专用语法("终于有一段 Verilog 像软件了——因为它本来就是软件");XSIM 的 GUI 跑法与命令行跑法(给 CLI 党);波形游标测量。
- **配套 Lab01-sim**:`tb_led_blink.v` + 把 led_blink.v 参数化改造。验收:游标测得 cnt[23] 周期 = 2^24 × 20ns(仿真时间),截波形图;参数改 4 位复现 ch00 实验 3 的 1.5MHz(与手算一致)。
- **新术语(首现)**:仿真(Simulation)、XSIM(Xilinx Simulator,赛灵思仿真器)、测试台(Testbench, TB)、激励(Stimulus)、仿真时间(Simulation Time)、时间标度(Time Scale)、参数(Parameter)、可综合子集(Synthesizable Subset)、系统任务(System Task)。
- **自测样例**:B/把 TB 的 clk 周期 20ns 改 10ns(DUT 不动),cnt[23] 仿真周期变多少?真实电路呢?(考察仿真时间 vs 物理时间)A/为什么 led_blink.v 里不能写 `#10`?C/TB 忘了释放复位,波形会是什么样?
- **衔接**:结尾钩子 →"显微镜就位,你的 Lab02 手术可以开工了。"

### 第 2 课 · 按键消抖:时间的第一个产品(约 5h,含作业;Lab02,需求书已布置)

- **钩子**:"你以为按了一下按键?金属片其实弹了 20 毫秒、二三十次。软件工程师的第一反应是 sleep(20ms)——但电路里没有 sleep,只有计数。"(现象钩子 + 专业身份钩子:第一次从零设计)
- **学习目标**:
  1. 能解释"计数器当时间滤波器"的思路:把"稳定满 20ms"翻译成"数满 100 万个时钟,抖动一来就清零";
  2. 能实现"稳定判定 + 边沿→单周期脉冲"两级结构,并用 TB 随机化抖动模型验证:按一次恰好 1 个 clk 脉冲、零误触发;
  3. 能独立通过三关验收(§2.3),再与参考实现对照,写 ≥3 行差异笔记;
  4. 能完整解释非阻塞赋值语义("全体读旧值、沿后齐更新"),兑现 ch00 埋下的"以后展开"承诺。
- **核心内容点**:抖动的物理来源;时间在硬件里的唯一形态=计数;tick/使能脉冲模式(全课程最重要的惯用法,此处诞生);边沿检测 `d & ~d_q`;按下/释放两态判定(消抖器本质是个 2 状态小机器——为 ch07 FSM 无痛预热);非阻塞完整语义(warn box:边沿检测为什么必须用旧值);组合逻辑毛 glitch 提醒(box);T 触发器把单周期脉冲"可见化"。
- **配套 Lab02**:按需求书自写(课程页给三关+提示阶梯+折叠参考,机制见 §2.3)。**板上验收**:按一次 LED 翻转恰好一次;快速连按 5 次 = 翻 5 次;按住不放只翻 1 次。
- **新术语**:抖动(Bounce)、消抖(Debounce)、单周期脉冲(Single-cycle Pulse)、使能脉冲(Enable Pulse / tick)、边沿检测(Edge Detection)、翻转触发器(Toggle Flip-Flop)。
- **自测样例**:B/稳定阈值从 1_000_000 改成 100,板上会怎样?(快速抖动被误判按下)A/为什么消抖计数要"抖动一来就清零"而不是"数满就锁存"?C/把边沿检测写成组合 always 块,哪里会出事?
- **衔接**:结尾钩子(埋雷,下一章开场直接引爆)→"你的消抖器把 P14 这根'野信号'直接接进了 50MHz 的世界——它 99.9% 的时候乖得像只猫。剩下那 0.1% 呢?"

### 第 3 课 · 亚稳态:时间对不齐的时候(约 3.5h;Lab03)

- **钩子**:接上章的雷。"你听说过数据竞争(race condition)吧?硬件世界也有,而且更阴险:它叫亚稳态,触发器的输出会'悬而不决'。你的 Lab02 一直踩在这层薄冰上。"(专业身份钩子:用他熟悉的软件噩梦类比)
- **学习目标**:
  1. 能用自己的话说出亚稳态成因(采样窗口内信号翻转 → 触发器输出悬而不决),并解释为何"无法消除、只能把概率压到宇宙年龄量级";
  2. 能解释打两拍同步器的原理与两个局限(只压概率不压延迟;一次只救 1 位);
  3. 能在双时钟 TB 里复现"多比特跨域直接采样 → 数值撕裂"的确定性实验(看得见的乱码,不是玄学);
  4. 能把 Lab02 回炉成 v2(同步 → 边沿 → 消抖计数),通过原三关 + 新增压力测试(随机异步延迟按 10 万次,零误脉冲),并说出多花的 2 个 FF 买到了什么;
  5. 能给出 setup/hold 的直观定义,并把它与 build.tcl 最后一行打印的 WNS 建立联系(为 ch04 铺路)。
- **核心内容点**:异步输入无处不在;触发器内部一瞥(不深入半导体,画"门赛跑"概念图);建立/保持时间;亚稳态;MTBF 直觉(每多一拍,指数压低);两拍同步器;多比特为什么不能各打两拍(数值撕裂;灰码只进路线图);回炉 v2 重构。铁律二("一个信号一个驱动源")在重构中回归。
- **配套 Lab03**:CDC 双时钟演示 TB + lab02_v2。验收(纯仿真):未同步多比特计数值出现撕裂的波形截图;v2 通过三关 + 压力测试零误脉冲(报告打印统计)。
- **新术语**:亚稳态(Metastability)、异步信号(Asynchronous Signal)、时钟域(Clock Domain)、跨时钟域(Cross-Domain Crossing, CDC)、两级同步器(Two-stage Synchronizer,"打两拍")、建立时间(Setup Time)、保持时间(Hold Time)、平均无故障时间(Mean Time Between Failures, MTBF)(选学)。
- **自测样例**:A/为什么打两拍不能用在 8 位总线上?B/两拍加到三拍,MTBF 变化方向?代价呢?C/v2 里消抖计数清零条件误接 raw key(未同步),错在哪?

### 第 7 课 · UART 发送器:用时间编码语言(约 5h;Lab05,难度顶点)
